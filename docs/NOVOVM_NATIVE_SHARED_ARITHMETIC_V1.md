# NOV 原生交易共享纯计算 v1

本轮将现有 Host 计算抽到 `novovm-protocol::native_arithmetic`，供 Host 和后续
证明 guest 使用同一份规则。生产入口已调用这些函数，旧公式只保留在测试对照中。
本轮没有构建 guest、生成 NOV 交易证明或变更协议结果。

## 当前范围

- 余额增加：保持原有 u128 饱和加法。
- 余额扣减：余额不足返回 None，否则返回差值；Host 保留原错误文本和状态表行为。
- `amm.swap_exact_in` 报价：保持扣费、整数截断、饱和乘法和饱和加法的原顺序。
- 已选定交换的池储备更新：保持正向/反向的原始增减规则。

模块不访问磁盘、时钟、环境、网络或 JSON，不负责签名、身份、nonce、池选择、
风控、手续费结算、持久化或回执根。报价的 Some(0) 和 None 保持区分，宿主原本
使用不同拒绝原因。储备更新函数的输入必须先由业务规则验证，它不是交换授权。
余额帮助函数被赎回和信贷等路径共用，因此也明确保留了其原有边界行为。

特别注意：保留饱和运算是保证本轮重构兼容，并非证明极端金额下的经济安全。
若要改成溢出拒绝或宽整数精确计算，必须另行定义协议行为并验证迁移，不能在
抽取共享代码时静默改变节点的共识结果。

## 验证

2026-09-27：

- 协议层全部 27 项测试通过。新增 4 项覆盖已知报价、零值、余额加减，
  以及旧实现对照：12096 组报价、41472 组双向储备更新和 144 组余额输入。
- 节点新增 2 项隔离测试通过：直接调用现有 AMM 分支，验证双方向的成功、
  余额不足和滑点拒绝；验证余额适配层的错误文本、归一化、显式零值插入及饱和值。
- 两包 `cargo clippy --lib --tests --locked -- -D warnings`、格式及 diff 空白检查通过。
- 这些是纯计算及内存业务分支测试，不是签名交易到持久化的整链测试。
- 原有 `amm_swap_exact_in` 两项持久化集成测试在第一项约两分钟无进展后终止，
  未取得通过结果，原因尚未确认。不能用隔离测试替代其持久化或 AOEM 运行验收。

```text
cargo test -p novovm-protocol --lib --locked
cargo test -p novovm-node --lib native_arithmetic --locked -- --test-threads=1
```

下一步仍需将完整交易规则逐步移入共享层，尤其是签名/身份/nonce 与父状态绑定，
再让 guest 约束实际状态转换及根。不能只证明上述算术，就将整个交易、区块或
`proof_sealed` / `finalized` 标记为有效。本轮不修改 AOEM、现用运行库或既有未提交
的第二轮确认改动。
