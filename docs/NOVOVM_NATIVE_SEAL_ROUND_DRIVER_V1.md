# 出块负责人缺席后的单高度接续驱动 V1

这次开发的是：**当前出块负责人没有响应时，让其余验证节点按已有安全规则，
换到下一轮，由新的负责人提出同一个候选，再收集足够的签名。**

前几刀补的是“哪些情况可以签、哪些情况必须拒签”。本切片把这些规则连接成
可以反复轮询的驱动器，先在本机受控消息环境中验证一条完整接续流程。
它不是聊天路由功能，也不是已经接入真实节点网络的自动出块服务。

## 这次能演示什么

演示场景是四个等权验证者，其中第 0 轮负责人始终不响应。其他三个验证者
各自使用独立的 seal store，不能共用一份签名记录代替三个节点：

```text
第 0 轮负责人缺席
  → 其余节点等待本地计时器到期
  → 收集 3 个有效超时签名，形成超时证书 TC
  → 顺序推进到第 1 轮，交换签名的换轮观察
  → 收集足够观察，形成换轮证书 NVC
  → 检查并持久化该候选的新轮准入证据
  → 第 1 轮负责人提出同一个本地已匹配候选
  → 收集 3 个有效准备票，形成 prepare QC
```

原负责人随后恢复时，已完成的节点仍重发前一轮 TC 与当前候选的 QC 证据包，
让这个**落后一轮**的节点按顺序追上同一候选。它不是任意落后轮数的历史同步：
节点如果缺少更早轮次的证据，仍需要另行取得，不能跳轮追赶。

这里的“3 个”只适用于本测试的四个等权验证者。实现依照固定验证者集核对
成员、签名和实际权重，法定人数要求超过总权重的 2/3，不把固定签名数量
当成任意验证者集的通用规则。

**流程终点是 prepare QC，不是最终确认区块。** 它证明规定权重的验证者
为这一候选签署了准备票，不单独证明业务执行正确、数据真正可取得，也不
代表已经完成链级最终性。

## 驱动器负责哪些事情

每个实例只负责一个固定 chain / epoch / height、固定 authority 与固定本地
候选，绑定一个本地签名者身份。它不拥有任意改换候选、验证者集或高度的权限。
这些配置按“签名者 + 高度”持久化绑定；重新打开时不能换一份 authority 或候选
继续使用同一身份的决定。绑定不保存绝对目录路径，不要求不同机器同盘符、同目录。

- 调用方提供单调递增的时间输入，驱动器在轮询时判断本轮是否超时；不用
  远端消息中的时间，也不以系统挂钟跳变作为签名授权。
- 收到消息时先核对认证的 peer 身份与消息中的签名者绑定，再验证消息上下文
  和签名。输入是已分类的共识对象，不是新的公共网络协议。
- 消息入口只收集和检查输入，不在收包调用栈中触发本地签名。需要生成本地
  签名时，由轮询入口显式接收本机签名密钥，继续走已有持久化安全门。
- 根据已收集证据推进超时、换轮观察、候选准入、提案和准备票的流程；不能
  因为“计时器到了”就越过证据检查、顺序轮次推进或本地候选锁。
- 重复轮询和重新发送使用已经持久化的本地决定；重启后继续核对这些记录，
  不能忘掉过去的签名再为冲突候选签名。未持久化的消息收集状态仍需重新取得。
- 轮询遇到安全检查或持久化错误后，实例锁定在 `Halted`，不再报告成功或继续
  签名；需检查原因后重新打开，并重新验证持久化记录。普通恶意或格式错误的
  远端输入直接拒绝，不因一次非法收包就把本地驱动器永久停住。

## 完成记录和资源边界

取得 prepare QC 后，驱动器先核对 QC 本体、对应 proposal 和 QC 索引，再同步
写入并读回校验固定的 QC hash，不能随后悄悄改成另一个 QC。重启和后续轮询
继续核对该完成记录及其引用，防止证据部分丢失后仍声称本轮已准备完成。
这是一条局部磁盘证据完整性检查，不是整库回滚、整库删除或物理故障保护方案。

输入与输出都设有编码预算，避免无法重发的证据在签名后才暴露：

- 每条已分类共识消息最多 192 KiB；这不是生产网络 wire 格式。
- 本地候选 subject 的编码最多 4 KiB。
- NVC 在候选准入之前限制为 128 KiB，给 proposal / QC 等其余字段预留
  64 KiB；完整输出仍必须通过 192 KiB 的总预算检查。
- 验证者集沿用 authority 最多 64 个成员的限制；每轮按固定验证者身份存放
  消息和去重，不为任意远端身份无限扩张收集表。

驱动器是 SUPERVM Host 内的编排组件。AOEM 继续负责通用执行内核职责，
本切片不修改 AOEM 内核、ABI 或 DLL，不向 AOEM 添加 NOV 专属共识业务。

## 还不能做什么

- **没有接入生产网络。** 现有 Overlay 仍限定第 0 轮；本切片没有放宽该
  边界，没有新 wire 协议、真实运行 CLI 或主节点生命周期接线。
- **不是连续出块。** 驱动器固定在一个高度和一个候选，不自动执行新交易、
  获取未知候选、切换到下一个高度，或更换 epoch / 验证者集。
- **不迁移候选锁。** 如果既有锁或最高 QC 与固定候选不兼容，必须停止，
  不为追求活性而自动解除锁。本场景可恢复，不意味着任意分叉都可恢复。
- **不晋升状态或最终性。** prepare QC 不触发 AOEM candidate 晋升、账本
  canonical 指针晋升或 commit finality；不会据此把 `chain_canonical`、
  `proof_sealed`、`safe`、`finalized` 置为 true。
- **不是四台实体机器验收。** 测试使用合成候选、测试密钥和受控消息调度；
  它不是真实 AOEM 独立重放、真实网络传播、断电恢复或手机聊天实测。

计时器不能持久化一个跨进程有效的单调时钟原点。恢复测试应区分“签名与轮次
决定没有丢失”和“重启后的等待策略”；不能把重新创建进程中的时间值当成
上一进程经过时长的证据。

## 如何验证，结果如何记录

测试重点是以下可观察行为，新增回归沿用既有封印 gate 入口：

1. 四个独立 store，缺席的第 0 轮负责人不参与，剩余节点通过消息交换取得
   第 1 轮同候选 prepare QC。
2. 法定人数不足、签名无效、来源身份不匹配、上下文错误或候选冲突时，不能
   越过相应安全门。
3. 超时前不能提前签超时；收包本身不能偷偷触发本地签名。
4. 重复轮询、重复消息与重启不能制造冲突签名；恢复仍受持久化决定约束。
5. 成功取得 prepare QC 后，最终性和 AOEM 晋升状态仍未改变。
6. 原负责人恢复后，借助已完成节点重发的前轮 TC 和 QC 追上当前轮候选；
   不把这一轮的追赶测试解释为任意轮数的历史同步。
7. 配置被替换、完成证据部分丢失、轮询失败以及输入超出资源预算时，分别
   按上述规则拒绝或停止；非法远端消息不能绕过校验，也不能代替本地签名。
