适用范围
这是理解技术与确认配置的说明，不是一份已经批准的发行方案。
依据当前 SUPERVM 代码中的 FreshGenesisConfigV1、原生签名协议、BFT V3
和生产验收台账。这里不生成正式私钥、不选择发行数量、不启动主网。

一、先理解“开链”和“发币”

开链：各节点从同一份创世配置开始维护一份账本。
发原生币：在这份账本中按协议建立 NOV 余额及其后续变化规则。
发合约代币：在某条链上的合约中建立另一套代币余额，验收路径不同。
当前新创世编译器配置的是 NOV；没有任意币名、符号、decimals 的配置字段。
因此改 UI 名称不等于修改协议资产，当前通过的原生测试也不代表任意合约代币已验收。

二、正式启动前要理解的配置

chain_id：正整数，交易签名会绑定它。测试链和正式链要明确区分；
          编号不是一个 IP，也不是从机器上自动识别的编号。

创世时间：配置中的起始时间，单位是 Unix 毫秒，所有节点必须一致。

protocol_config_commitment：运行时业务协议配置的哈希。
          由程序根据最终环境生成；不能凭空填写，也不能混用不同节点的值。
          它不替代二进制包校验，发布包还需单独统一。

allocations：开链时“地址 -> NOV 数量”的清单。
          配置金额是整数最小单位的十进制字符串，不接受小数或科学计数法。
          要先确认钱包显示单位与账本单位的换算，再填写数量。

total_initial_nov：上述清单的合计，程序要求精确相等。
          它表示初始供应量，单独这一项不等于永久供应上限。
          若要承诺后续不能增发，需要另行验证全部增发、治理和升级权限。

validators：初始验证者公钥及投票权重。
          公钥可以用于核验身份；私钥用于签名，必须保管在对应节点的安全位置。
          不能把同一个验证者私钥复制到多台同时签名的节点上。

三、验证者、账户和 relay 各做什么

账户密钥：控制资产或签署业务交易。
验证者密钥：对区块和共识消息签名。
网络身份密钥：对传输节点进行身份认证。
TLS 证书：保护 WSS 连接。
这几类材料职责不同，当前测试也使用不同的签名和传输密钥。

四个等权验证者的严格大于 2/3 门槛，需要至少三票。
测试必须证明两票不确认、三票确认；还要测试恶意消息、分票、断网与恢复。
三票确认本身不是所有故障场景都安全和可恢复的证明。

relay 是转发通道。它不拥有用户余额、不代替验证者投票，也不执行 AOEM 业务。
阿里云服务器可以作为公网 relay 候选；是否使用，需要核对系统、TLS、端口、
资源与网络可达性。单 relay 仍需独立验证故障后的替代路径。

四、你已有的设备如何参加验收

本机 Linux：构建、自动化测试和证据汇总。
四台 Windows：可作为四个独立数据库、独立身份的实体节点。
阿里云：公网 relay 候选及跨公网测试入口。

先收集 hostname、当前 IPv4、操作系统、内存、磁盘余量及登录方式。
同一局域网内的四台机器可以完成实体多机验收，但仍共享停电、路由器、
宽带等故障风险；生产容灾不能仅按机器数量判断。
历史 192.168.x 地址可能已经变化，以本轮采集和实际连通性为准。

五、正式配置应如何批准

1. 技术团队给出配置草案及人类可读汇总，不包含私钥。
2. 你逐项确认链身份、资产单位、初始数量、每个分配地址和验证者身份。
3. 使用测试配置演练初始化、交易、停止、恢复，保留日志与哈希。
4. 批准最终版本后固定创世哈希、协议配置哈希及发布包哈希。
5. 每个正式节点核对同一套批准材料后启动到全新、独立存储。

测试中的固定种子、1000 NOV 余额和测试 chain_id 都只是测试夹具。
不复制测试数据库到正式链，不把 artifacts 中的测试身份当成正式密钥。
一旦正式链按某份创世启动，再修改该创世不是普通“改配置并重启”。

本轮已实现签名用户的回环 RPC、持久交易队列和按高度追赶，说明见
NOVOVM_FRESH_CHAIN_INGRESS_RECOVERY_V1.txt。queued 只表示本机持久入队，

当前接口不是已公开的互联网钱包服务；公网接入需要受控 HTTPS 网关及独立验收。
尚未处理无候选 leader 离线活性等故障，不能用本机 PASS 替代所有上线门禁。

七、现在需要你提供什么

目前只需要设备清单和可操作的登录方式，不需要立刻决定总量。
在 Windows PowerShell 查看：
hostname
Get-NetIPAddress -AddressFamily IPv4 | Where-Object {$_.IPAddress -notmatch '^(127\.|169\.254\.)'} | Format-Table InterfaceAlias,IPAddress

也可以使用本轮新增的 scripts/novovm-production-machine-inventory.ps1。
脚本随本开发检查点提交；其他设备须先同步到包含该文件的版本。
确认各机器 SUPERVM 仓库的 scripts 目录中存在该脚本后，在仓库根目录执行：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/novovm-production-machine-inventory.ps1 -MachineLabel win-1
其余三台分别使用 win-2、win-3、win-4。脚本会打印新 JSON 的位置。
它只读取设备/版本信息并写一份报告，不改防火墙、不启动服务、不采集密钥。
报告中的 IP 只是候选地址，不等于已经可达；本机 Linux 分支已运行验证，
Windows 分支仍需在设备上执行确认。提交报告前可以检查其中的主机名和 IP。

阿里云请提供系统类型、公网入口，以及当前使用 SSH 别名还是 Workbench。
不要发送密码、私钥、助记词或云访问密钥；正式账户在本地生成并保管。
技术验收过程中会逐项解释配置，让每一个不可逆决定都有可核对的依据。
