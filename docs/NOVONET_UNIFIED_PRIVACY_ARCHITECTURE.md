# NOVONET 统一隐私网络架构

NOVOCHAT 自安装、建立身份到消息补收均使用同一 NOVONET。产品只显示连接、等待和送达等实际状态。直连、转发、多跳及信箱由网络在联系人授权和隐私要求内自动调度。

## 发现与入网

1. 设备恢复或创建本机身份和专用通信密钥。一次联系人核验建立关系和通信权限。正式 UCA 状态、资产账户、钱包签名和订阅权益分别接入各自的原生接口。
2. 使用同一个发现入口和候选库。冷启动可以从安装包携带的多个独立引导源开始。已知节点、联系人提供的引导、已连节点交换和局域网邻居也可提供候选。人工邀请适用于可选引导与恢复。
3. 节点使用自身通信用途钥发布地址、端口及服务声明。发现服务验证持钥和签名、链域或服务范围、时间、序号及声明适用的服务限制。客户端验证同样的约束，并按序持久保存撤销与续期历史。可发现性只让记录进入候选库，实际通信仍取决于认证和用途授权。发现数据限于服务节点所需的公开信息。
4. 引导器只提供可验签数据。至少保留能独立到达和更新的来源。曾信任的签名者、服务角色和地址分别维护，禁止从地址相同推出同一身份，或从三把不同公钥推出三个独立运营方。联系人、账户关系和钱包信息留在各自授权范围。

## 统一路径调度与投递

NOVONET 只维护一条自适应通信执行链。NOVOCHAT 执行同一套隐私规则。私密 APFL 在原执行链内提供候选验签、逐跳保护和业务适配，共用原有网络状态、路径选择、故障恢复、消息队列和设备回执。迁接通过后清除独立私密入口和执行器。引导、局域网、联系人与动态寻址提供同一候选库的数据，任何固定站点都不能成为日常通信的前提。

```text
设备身份及联系人授权
  → NOVONET 发现与签名验证
  → 同一候选库和签名状态
  → 按用途及隐私门槛过滤路径
  → 按可达性、质量和预算选择已合格候选
  → NovoRUDP / Iroh 载体和 APFL 服务
  → 原消息队列、寄存、领取、设备持久回执
```

每条路径都执行默认隐私要求。直接交换地址须限于双方明示授权及允许的范围。保护通信双方网络位置的路径按角色、信任与运营故障域审核。跳数由实际隐私目标和受验证载体决定。旧直连、L4 签名会合与动态地址更新接回同一调度。网络变化、首选入口故障或节点退出后重新选择仍合格的路径。候选耗尽时，保持原件、原期限及原授权。

备用路径与备用寄存分别验证。多路径指向同一终点只能降低路径故障。发送设备离线前，独立节点实际保存完整密文后才具备离线领取能力。设备回执以接收设备完整性认证和持久存储结束为准。

## APFL 服务准入

公开发现允许任何符合协议的节点签名发布自己的服务声明。私密转发和信箱使用另有服务边界。现有接入优先复用 ML-DSA-65 会话绑定认证、新鲜挑战和防重放机制，由服务按用途验证具体权限并签发有限的会话授权。会话授权绑定请求方、服务及用途，明确期限、请求限额、资源预算及撤销。密文的读、写、领取和回执仍需各自的能力验证。在线重试、换钥、重复调用和耗尽配额进入同一资源所有者处理。已有自管客户配置继续作为可选的站点策略，公开候选发现不使用人工登记名单。

已有的 APFL V8 私密终点支持提供者选择 `autonomous_mailbox`。该项写在原 owner 的 `private-apfl-policy.json`，包含 `session_seconds`、`requests_per_minute`、`tracked_devices` 和可选的 `denied_clients`。自主终点须先由本机 owner 设置明确的存储上限，并继续使用原连接、字节和事务预算。会话在原 V8 握手完成后获发，绑定该次 Finished 会话，无可转移凭证。请求按批次中的业务项扣减，容量协商计一项。相同公钥只占用一个活动会话，重连复用当前一分钟内的剩余次数。到期或额度不足时，终点终止此流。原信箱的读写能力、去重和回执规则继续执行。

转发 owner 可以在同一份策略设置 `autonomous_origin`。其 `admission` 字段沿用自主终点的上限字段。`renewal_bytes_per_minute` 从既有 `max_wire_bytes_per_minute` 划出首跳续签预算，原业务预算为扣除后的余额。启用后，首跳接受未预登记设备的持钥证明，只连接本机批准的原后继。后续节点保持相邻签名验证，终点按自己的服务策略和信箱能力裁决。续签使用独立字节预算，在业务会话仍活跃时可取得新声明。

原 owner 将准入窗口、剩余配额和逐设备撤销保存在现有 `mailbox.sqlite`。重启须重新完成会话认证，未到期用量和撤销仍生效。尝试认证计入单独的提供者预算，默认数值采用 `requests_per_minute`。owner 可以通过保护目录中的 `private-apfl-revocations.json` 热撤销，内容为完整通信用途公钥字节数组的列表。文件更新须原子替换。已经读入的撤销写入原库，移去文件或删掉条目均保留已生效的撤销。预算、撤销和后继验证分别作用于本站，不能代替手机对整条路径的资格检查。

## 链上 UCA

本机持钥及联系人授权支持基础通讯。SUPERVM 完成正式 UCA 自主开立、确认、设备授权和撤销后，原生客户端按用途接入可信状态。应用打开与合法联系人聊天无需等待钱包 RPC。ZK 留给需要隐藏主体的权限、额度或资格证明，并按实际证明系统验收撤销和隐私。测试阶段使用现有开发环境，真实收费保持关闭。

## 主线迁接与验收

本规范由现有 main 承载。首次自主入网、已装手机恢复和链上 UCA 是不同验收项目，均在同一产品中交付。迁接保留原消息数据库、受保护密钥、回退 APK 和云信箱寄存义务。已批准配置的续签声明、租约和撤销状态沿原事务持久化。

2026-11-24，NOVOCHAT 把原独立 APFL 连续任务入口收回同一自适应任务。候选先执行双向联系人授权，再进入同一端点生命周期，继续复用原消息日志和设备回执。端到端内容保护适用于每条候选，彼此地址的可见性按授权范围核对。v127 ARM64 打包签名核对通过，Flutter 444 项及 Android JVM 174 项通过。无配置冷启动、两设备 T1、Wi-Fi／蜂窝切网和原消息补投仍待实网验收。本轮无需调整节点部署。见 [NOVOCHAT main 实现](https://github.com/XujueKing/NOVOCHAT/commit/48763ebd290a8d740facbe43a1508b9cdb627966)。

1. 全新设备无旧缓存、无人工邀请文件、无逐客户静态登记。首个引导源故障后，独立来源提供当期签名候选并建立合格会话。
2. 先在既有两机确认实际路径认证，再验证首选 IP 和端口故障。一台 Wi-Fi、一台蜂窝，保持原隐私要求，合格路径恢复后使用原文字和 PNG 验证接收端持久保存和发送端设备回执。
3. 分开核验签名伪造、范围错误、序号倒退、角色和故障域不合格、声明与服务权限撤销、资源耗尽、设备与节点重启、L4 直送或寄存路径恢复。
4. 局域网用于两设备基础回归。真实互联网验收覆盖 Wi-Fi／蜂窝自动会合、双向切网、断网回连、端点变更、候选失效和后台任务恢复。核对原消息标识、接收端持久保存和发送端设备回执。

当前原生节点 locator 已有独立的公开 RPC。它使用绑定会话验证发布者，在入存前校验原生签名和网络范围，并与联系人私密记录分离。公开发现会话使用原请求预算，发布记录在当前存储实例中的可见期限受签名期限约束。已存有效记录抵御签名序号倒退及同序冲突。跨实例的持久撤销和序号、公开 locator 到私密路径资格的接线、独立初始引导源和独立密文副本仍待验收。上述验收以实际部署和手机结果为准。
