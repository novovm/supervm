新创世链：签名交易准入、历史追赶与进程恢复

范围
本切片接入现有 FreshChainLifecycleV1、AOEM 独立执行与 V3 最终性路径。
不是旧 pending executor，不修改 NOVORUDP frame，不授予 RPC 签名/发币权限。
本机验证通过也不等于公网、Windows 多机、物理断电或生产发币获准。

启用方式
保留已经批准的原 seal 配置、创世与身份；本切片不生成这些材料。
seal 配置需要显式开启 follow_finalized_tip、receive_successors、propose_successors。
主节点原 native_execution_tick 启动参数保持不变，额外设置：
NOVOVM_NATIVE_FRESH_RPC_BIND=127.0.0.1:18545
不设置此变量就不监听 RPC。拒绝 0.0.0.0 或公网地址的直接绑定。
远程用户接入需另外部署受控 HTTPS 网关、身份/速率控制与监控；不能把
当前回环 HTTP 当作已完成的公网 API 服务。不要将验证者私钥交给网关。

接口
HTTP POST /，Content-Type: application/json，带 Content-Length。
仅支持单个 JSON-RPC 2.0 请求；不支持批处理、chunked 或 HTTP pipelining。

提交已签名的 NOV native execute wire（十六进制，0x 前缀可选）：
{"jsonrpc":"2.0","id":1,"method":"nov_sendRawTransaction","params":["<signed-wire-hex>"]}

按规范化交易哈希查询：
{"jsonrpc":"2.0","id":2,"method":"nov_getTransactionStatus","params":["<tx-hash-hex>"]}

节点状态：
{"jsonrpc":"2.0","id":3,"method":"nov_chainStatus","params":[]}

普通用户只需自己的账户签名，不需要验证者密钥或绑定验证者 transport 身份。
转账等业务应使用已有受支持的 execute 请求；本切片不新增业务执行类型。
返回 status=queued 表示通过链域/签名/账户权属认证，并已同步写入本机 RocksDB
WAL；不代表已执行、远端已接收或达到共识。Future nonce 可排队，选块时必须
按已验证父状态重新检查精确 nonce 顺序。不同交易占同一账户 nonce 会被拒绝。
相同交易重试不重复入队；已最终化交易的重试返回 finalized，而非再次执行。
status=finalized 只来自经过最终性验证的父状态和累计回执，receipt.status 仍需
检查：已最终化不等于业务执行成功。finalized_tip_height 是当前已确认链尖高度，
不是该笔交易所在高度。unknown 不表示执行成功，也不保证交易从未提交过。

持久队列
队列目录由 seal_store_path.with_extension("txpool") 派生，启用
propose_successors 时打开。该目录纳入输入/输出路径隔离检查；不得与密钥、
账本、执行库或其他写入目录重叠。RocksDB 排他锁阻止同时开两个写入者。
队列绑定 chain_id 和创世承诺；恢复时重新验证记录哈希、签名、nonce 唯一性和容量。
无身份记录、错创世或损坏数据都报错，不静默清空、不伪造成功。
限制：单交易 64 KiB、总计 1024 条/16 MiB、每个签名账户 64 条。
满队列或 nonce 冲突必须由客户端处理错误；未最终化交易不因重启被删除。
已最终化或 nonce 已被其他最终化交易消耗的条目通过同步批写移除。
任何失败写入不得返回 queued；不确定持久化错误使本生命周期停止接收新工作。
已入队交易按有界速率在验证者之间传播；非 leader 也能接收用户提交。

多高度追赶
receive_successors 启用时，在经过身份绑定的 NativeSeal 控制通道发送 NOVHIST1
请求。请求绑定 authority commitment、创世承诺和明确的下一高度。
每个绑定 peer 只保留一个请求/响应，限速重试，不接受未绑定来源的任意历史扫描。
任何持有该高度已验证归档的验证者都能响应，不依赖原 proposer 在线。
响应包含原 prepare QC、完整 DecisionCertificateV3 及有界块体分片。
证书中的原签名者不因转发者身份改变。接收方只执行当前父块的直接后继，逐高度
验证 ancestry、签名、块体承诺及本机 AOEM 输出，再经原发布/最终性路径晋升。
不直接复制远端状态或把 send_to/transport ACK 当作最终化；不跳过中间高度。
重复请求不重置大块分片发送进度；接收者请求更高高度时才推进响应。
该协议要求各参与节点使用本切片版本；旧二进制不会自动获得历史服务能力。

时间与消息丢失防护
FreshChainLifecycleV1 对本机时钟最多允许 30 秒未来偏差。
收到的后继块体在创建/执行工作区之前检查时间；未来块被拒绝并等待重传。
已有执行候选或最终父状态超出本机时钟上限时，主节点停留 clock_waiting，
不会继续签名或自动构建后继；校时恢复后继续，不修改原候选、nonce 或待执行队列。
状态新增 clock_waiting、future_timestamp_rejected、max_future_block_time_ms。
这不是跨机器校时服务；部署仍需时钟同步。历史块只有过旧不会被拒绝，过于未来的
最终性归档同样暂不导入；测试中的虚拟时钟只用于 crate 内测试入口。

V3 同一轮次收到 DecisionVoteV3 / DecisionCertificateV3 而本地 prepare 消息丢失时，
先验证完整 transport 绑定、来源及 V3 签名，再将携带的 QC 交给原 prepare 门禁。
实际持久化和签名仍在本地 poll；不跳轮、不放宽 NewView、timeout 或安全锁。
补入的真实回环 WSS 测试只给落后节点投递 V3 消息，丢弃其 prepare 流量，检查
恢复、坏签名拒绝及重启证据不变。它不等于已解决跨轮次 prepare 分票活性。

已超时节点的迟到 QC
V3 服务恢复持久 timeout 后，若本轮尚未 Prepared，不会再将迟到 QC 提升为
旧轮决策签名入口。否则签名阶段虽会正确拒绝，却使正常延迟流量导致服务停机。
现在保留原 timeout/安全锁，继续既有 TC/NewView 换轮；不回退轮次、不抹除锁。
已 Prepared 的节点继续原决策票重传，不因该保护丢弃已落盘的 QC。
V3 的相同 execution target 决策票可沿用原协议在不同 round 见证之间合并；
每个节点使用自己的已验证 QC 归档，不替换原始签名。不同执行目标仍不可混合。

Prepared V3 pacemaker 与 2+2 恢复
Prepared 不再等同于停止 V3 计时。只有原本地决策票及其锁、marker、原 QC、
proposal/admission 均可验证，并且还没有完整决策归档，才继续参与 timeout 和
同一不可变候选的新轮 prepare。初次决策票尚未持久化时仍先完成原签名入口。
active round 只能由原加权 quorum TC 推进；原 Prepared pin 和 V3 决策签名
不改写。QC 重传按该 QC 的历史轮次读取持久见证，不混用 active round 的提案。
因此 active round=1、prepared QC round=0 可以同时成立，不代表降低签名门禁。

NewView quorum 的全部最高 QC 先验证签名及本地候选匹配，再经既有持久导入路径
落盘；不放宽非零轮历史 admission，不释放候选/高度锁，不修改协议 wire。
完整决策归档后停止该 Prepared pacemaker；归档和重启仍走原 V3 验证链。

无候选换轮的本地基础能力
with_verified_finalized_parent_round_v1 在 workspace、AOEM authority 和 ledger 锁
共同保护下，重新验证当前最终父块、创世/namespace、完整 AOEM 输出和最终性证明。
回调只得到只读父块换轮作用域，授权高度严格为 parent.height + 1；它没有已执行
候选能力，不能用于 prepare subject、proposal、vote 或 decision 签名。
回调不能再次进入 workspace/authority API 或通过其他句柄变更同一账本。

该作用域复用现有 Timeout / NewView 协议、同步持久化和签名者 watermark，
不新增 wire，不减少 quorum，不清除候选锁。只有本地单调计时器到期才产生新的
timeout；超时证书推进轮次不代表产生候选或最终化。重启可以取回原始签名证据，
新计时器重新等待完整间隔；缺失/损坏安全记录拒绝重新签名，而非自动修复。
NewView 的 highest_qc=None 不表示没有候选锁，也不授权替换任何已锁候选。

候选前自动 pacemaker
FreshChainLifecycleV1 现在于显式 receive_successors 模式中保留父块换轮能力；
自动构建候选仍要求 propose_successors。未开启接续的 publication relay 仍不签名。
控制 Timeout/NewView 与块体/交易分别有界排队，每个绑定 peer 每组最多 4 项，
统一 ingress_per_poll 预算按 peer/队列轮询；未知来源、错链或超大 payload 拒绝。
enqueue 只排队，poll 中重验传输 hash/delivery/source、权威和签名后才处理证据。
父状态尚超出允许未来时间时 clock_waiting，不处理候选或产生新 timeout 签名。

轮次从同步落盘状态恢复；本地计时到期才新增 timeout，3/4 加权 quorum（等权
四验证者配置）形成超时证书后逐轮推进。非零轮提案必须具备有效 NewView quorum；
新 leader 按当前高度/轮次自动选择，从持久交易池构建并实际执行候选。
接收者同样重执行块体。创建候选服务时持久绑定候选 owner，并重新验证/接入
NewView admission，后续 poll 继续原 V3 proposal/vote/decision 调度。
已超时旧轮块体不得回退轮次；带下一轮证书的块体只能经验证的超时证书推进。
已有 highest QC 的 NewView 不授权任意新候选，也不清理原候选安全锁。

状态新增 parent_pacemaker（height、round、local_timed_out、new_view_ready、
timeout_count、observation_count）及 parent_round_signing_enabled。
publication 的 signing_enabled=false 仍只表示它不签区块；父块 Timeout/NewView
签名能力应看新字段，不能把 publication 字段误读为整个节点完全不持有 signer。
候选交接后 parent_pacemaker 清空，由原 candidate service 接管。
