# 原生交易共享 nonce 规则 v1

`novovm-protocol::native_nonce` 收纳现有确定性规则，没有增加依赖：

- V2 身份：既有方案标识、NUL 分隔符、已鉴权 Ed25519 公钥。
- 链域身份键、交易签名预留摘要、链/身份/nonce 持久去重键。
- 连续 nonce 校验和 checked successor；拒绝回放、跳号及 u64 溢出。

宿主入池及持久化路径通过原有适配函数调用共享摘要实现；候选批次与主执行批次
调用同一 advance 函数；持久提交复用 successor。原有哈希域、大小端、十六进制
输出、状态方案标识和错误文本保持不变，不需要迁移已有数据库。

身份编码不等于鉴权：调用方仍须先验证签名与签名者，再验证链域、执行主体及
父状态。真实 Ed25519 验证仍由现有 Adapter/AOEM 路径执行，本轮没有把它迁入
证明 guest，没有增加信任调用方“已验证”布尔值的捷径。

不移动宿主环境配置、pending 预留、数据库访问、幂等回执处理或历史迁移策略。
共享 advance 不修改输入；先拒绝 nonce 不匹配，再检查溢出，保持既有批次顺序。
持久提交仍保留原来的溢出检查与幂等处理顺序。

测试包括旧编码/哈希字节对照、域隔离和序号边界，以及现有节点签名、地址别名、
候选批次、持久 nonce 重开和冻结状态根回归。

测试通过；两包 `clippy --lib --tests --locked -- -D warnings`、格式及空白检查通过。
不能用共享规则抽取宣称已有完整 NOV 交易有效性证明、多机验收或主网最终性。
