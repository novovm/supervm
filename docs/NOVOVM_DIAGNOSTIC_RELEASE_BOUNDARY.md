## 分类与保留

| 类别 | 当前位置/用途 | 发布处理 |
|---|---|---|
| 产品实现与必要运行库 | Cargo workspace、审定 AOEM 及产品资源 | 由产品构建契约和资源清单选择 |
| 持续回归测试 | 协议、认证、内存安全、打包守卫等 | 保留源码及 CI；不作为用户默认启动服务 |
| 一次性调查工具 | CDB/PT/TTD 实验、资格崩溃程序、插桩标准库、历史采集助手 | 根因调查期间保留；发布前移出产品源码交付集，按复核价值归档或清理 |

| 公开审计 | artifacts/audit 中脱敏报告、必要脚本和摘要 | 作为研发档案；不等于产品组件，发布源码前单独分类 |

## 正式开源/制品发布前门槛

1. 对实际选定提交的 tracked 文件及发布 staging 清单分类，列出一次性调查目录、
   临时二进制、测试启动任务、调试环境变量和插桩依赖；不宽泛删除 tests 或 artifacts。
2. 对不再需要的诊断工具按用途归档或移出正式源码交付集；复现证据按当前保留要求
   处理。有效回归测试、产品资格检查、必要运行库和正常诊断能力继续保留。
3. 检查实际 Cargo targets、features、构建脚本、CI 和安装/启动入口，防止默认运行
   一次性资格进程、启用 PageHeap/PT/TTD 或安装调查用 WER/任务配置。
4. 检查最终源码归档及二进制包的文件清单，确认无私钥、测试库、DMP、ETL和诊断
   副本；核对包内 EXE/DLL 来源与哈希。保留清单及检查结果再作发布判定。
5. 区分产品包、源码归档、完整 Git 仓库历史。gitignore 不会清除已提交文件；
   export-ignore 也只影响相应 Git archive，不会从 clone/历史中移除材料。
   本轮不重写历史，不能把“未来清理”表述为“已从 Git 删除”。

调查工具的完善不是 NOVOVM 根因修复。根因未定位前不提交猜测性修复，不恢复双中继。
