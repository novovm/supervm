# 直连优先路由恢复修复（2026-09-20）

## 本次修复

现有 overlay_runtime 在直连失败时已支持中继与队列回退，但 CoolingDown 状态即使超过截止时间仍不可用，导致保留健康记录的调用方无法恢复尝试该路径。本次改为截止时返回 Degraded（允许尝试，不宣称已恢复健康），显式 Failed 状态仍保持不可用。

同一路径多次失败此前只保留第一条记录。本次合并最大失败时间和最大冷却截止时间，避免新失败被忽略；结果不依赖同一路径记录的输入顺序。

## 验证

cargo test -p novovm-network --lib overlay -- --test-threads=2：35 项通过。
包含新增的冷却边界、重新选择直连、Failed 不复活、重复失败及输入乱序回归；现有握手、密文篡改、防重放和直连/中继 loopback 测试通过。

## 范围

只修改通用网络路由恢复逻辑，不修改共识、AOEM 或密码协议。本次没有部署到手机或服务器，不代表双机网络切换已验收。

当前健康快照仍使用调用方提供的 Unix 毫秒时间；单调时钟探测、吞吐/丢包退化检测、切换滞回及手机端调用接入尚需核对实现。此次没有新增抗封锁寻址，也不将已有防重放等同于无法被被动复制或追踪。

## 连接保活计时修复

实际 product_mainline_overlay 单对端和多对端中继会话的心跳改用 Instant 单调时钟，间隔仍为 2 秒；发送后从实际发送时间重新计时，不补发积压心跳。将检测放在循环顶部，避免多对端缓冲消息分支的 continue 长期跳过心跳。

这是已有会话循环的保活修复，不是新增 RTT 测量、认证探测应答或质量选路算法。现有原型 OverlayRouteHealthSnapshot 的字段尚未成为这条运行链路的自动质量采样源；后续需明确接入点，不能将独立路由单元测试等同于手机端已实现智能切换。
验证：cargo test -p novovm-node --lib product_mainline_overlay -- --test-threads=2，22 项通过，包括双向投递、三节点 mesh、重启恢复和备用中继切换。尚未部署到设备。

## 运行链路重连防抖

移除认证中继一连上就清零连续失败次数的行为。连接维持不足 30 秒就结束时保留失败次数，继续采用现有有上限的指数退避；连接维持至少 30 秒后才重置重连预算。时长使用 Instant。这只是连接持续时间门槛，不证明 RTT 良好或消息已送达。

重连等待改按单调时钟的实际耗时计算；处理队列占用的时间计入等待，不再每轮处理完后继续累计完整睡眠时间。保留停止检查和队列资源回收。

本次仍未实现持续 RTT/吞吐采样或按质量主动换路。连接成功路径当前传给 record_relay_success 的 RTT 仍为占位值 1，后续必须用可关联、已认证的测量替换，不能把握手总耗时直接当成网络 RTT。
本批验证：product_mainline_overlay 相关 23 项测试通过，包括新增连续短连接退避、稳定期边界与上限检查，以及已有中继切换和三节点恢复回归。未部署到手机或服务器。

## 心跳应答测量与失联恢复

ProductRelayClientV1 复用现有已认证连接上的 Heartbeat/HeartbeatAck，不更改线协议。每条连接只允许一个未确认心跳，重复调用不会重发或重置起始时刻；收到应答后计算单调时钟往返耗时，使用 7/8 历史值与 1/8 新值平滑。该指标包含中继处理和本机调度延迟，不是纯网络 RTT，也不证明最终对端已收到业务消息。

未确认心跳达到 15 秒时，heartbeat、recv_event 和协议读取循环返回终止性超时，区别于正常空闲轮询超时。主会话循环已有的断线/轮换/退避路径消费此错误。原有半包与写入期限保持有效。

移除连接成功时伪造的 1 ms RTT。会话结束、准备重新选路时，若有真实心跳测量才反馈候选池；随后仍记录导致会话结束的失败。尚不执行仅因 RTT 升高就断开健康连接的主动换路。

V1 应答没有探测 ID，单个待确认请求只适用于现有有序连接；不能据此声称支持无序 UDP 探测、防恶意中继伪报或抗追踪。端到端质量探测、吞吐/丢包采样及手机端接入仍待完成。
本批验证：product_relay_client::tests 13 项、product_mainline_overlay::tests 23 项通过。较宽的 product_ 筛选共 84 项在长时间无进度时中止，未记为通过。真实中继客户端测试检查应答测量、重复心跳不重置计时、模拟过期后的终止性错误；尚无手机或公网故障注入验收。

## 直连打洞探测接收修复

直连入口目前是 product_nat 的签名探测，product_peer_runtime 仍明确为 relay-first 验证入口；本次没有把它描述成已完成的持续 P2P 数据通道。

ObservedEndpoint 与 NAT punch 请求现在只接受来自预期 SocketAddr、且通过现有签名/身份/nonce 校验的应答。杂包、错误 JSON、旧 nonce 不再立即结束探测，后续合法应答可在原期限内成功。使用单调时钟限制总接收时间，同时最多处理 64 个包，防止输入洪泛无限占用 CPU；因此持续洪泛仍可能导致失败回退，不承诺抗阻断。

保留原有签名和回退策略，不修改线协议。操作退出时恢复调用方原始 socket read timeout。该函数需要独占探测 socket，不能与业务消息接收器并发使用，因为它会消费并丢弃无关数据报。

本次不实现持续直连 RTT/吞吐监测，不变更共识；手机接入和公网验证尚未完成。
验证：cargo test -p novovm-network --lib product_nat -- --test-threads=2，4 项通过，含真实 loopback UDP 探测及错误来源、坏包、nonce、超时恢复回归。
