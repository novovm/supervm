## 必须恢复的架构边界

恢复的是实质职责和产品接线，不是给新简化节点改名。

```text
crates/novovm-node  唯一节点总控
  → 原有网络、RPC、账户、EVM、治理等产品模块
  → Host 业务规则与语义计划
  → novovm-exec 统一执行门面
  → aoem-bindings 通用 ABI
  → AOEM 物理执行、CPU/GPU 调度与 RocksDB 持久化
  → 结果验证、共识发布和查询投影
```

| 边界 | 应承担的职责 | 不允许的替代解释 |
| --- | --- | --- |
| novovm-node | 启动、配置、生命周期、网络/RPC、共识总控及停止恢复 | 只留下名字，实际产品面全部换成独立 Transfer 测试链 |
| Host 业务层 | 定义鉴权、费用、nonce、失败规则；编译访问集、依赖、条件交换及执行计划 | 先串行算完整业务结果，再把 AOEM 落账叫作完整并行执行 |
| novovm-exec | 统一会话、能力选择、预算及 AOEM 执行/存储/证明调用边界 | 各模块自行散落 FFI，另造相互冲突的调度和状态 owner |
| AOEM | 通用任务的实际计算、后端调度、状态耐久提交和执行结果输出 | 加入 NOV 专属账户、余额、收费、治理或共识政策 |
| 共识与查询 | 验证结果、唯一状态发布授权、只读查询投影 | 第二份权威账本，或用 QC/本地读回冒充完整业务有效性证明 |

CPU 回调不是天然错误：新实现确实把部分业务计算交给 AOEM worker。
但不透明 `FnOnce` 不会自动转成 GPU 算子。应复用 AOEM 已有统一语义与异构
能力，验证实际调用和计算归属；不能只改函数名、只开线程或另造 CUDA 路线。
AOEM 会话常驻，不逐交易/逐批初始化。物理持久化仍由 AOEM 的 RocksDB
后端承担，Host 可定义记录格式及消费完成结果，不能另开权威执行库。

搬迁前 `novovm-exec` 已同时提供 wire、APFL bulk、compute 和 V3 storage
适配；新 `runtime/novovm-aoem/src/compute.rs` 也注明源自旧实现。因此没有
必须废弃统一门面才能采用新流水线的技术前提。最终绑定应收敛为一个公共
边界；迁移期间不得让两套适配各自拥有同一业务状态。

即使某段 Host 执行实现整体不适用，也只替换对应计划、编排或状态交接模块，
不连带废弃节点、网络、EVM 等产品。保留框架不等于旧代码逐行不可修改。
