1. **语义被粗粒度冲突替代。** 相同账户即连通会把只收不支的汇聚账户当成
   必须串行的冲突；组件并行不是 OCCC 条件交换已经接通。须显式表达 debit、
   credit、nonce、费用及失败效应，并验证交换条件，不能靠饱和加法假定等价。
2. **执行与持久化的所有权容易混淆。** 早期 Host 算完整结果、AOEM 写 KV；
   当前 Transfer 已有真 AOEM 计算，但完整统一语义计划尚未闭合。Host 的
   业务政策所有权既不等于宿主应串行算完，也不意味着要把政策写入 AOEM。
3. **阶段组织仍约束整条链。** fresh 生命周期的接入、候选准备、存储与
   共识存在同步耦合；新单候选 worker 试验性能反而退步。不能靠旧 async
   开关、合成 telemetry 或“有线程”证明流水线已完成。
4. **增量账本不等于增量工作量。** 三树点读/更新已接入，但回执、逐点存储
   往返和重复完整产物/历史验证仍有放大。应按批次和修订边界组织，不提高
   快照上限或删除校验，不增加第二权威账本。
5. **证明与最终性的契约未合拢。** 当前 seal 明确是本地 AOEM 重执行/回读
   加 BFT decision QC，`zero_knowledge_execution_proof=false`；native-auth
   guest 只覆盖签名/nonce 关系，不证明余额、费用及完整状态转换。

依据入口：[Transfer 调度](../legacy/supervm-20261002/crates/novovm-node/src/native_transfer_dispatch.rs)、
[候选执行](../legacy/supervm-20261002/crates/novovm-node/src/native_candidate_execution.rs)、
[发布状态](../legacy/supervm-20261002/crates/novovm-node/src/native_block_seal_publication_driver.rs)、
[鉴权证明](../legacy/supervm-20261002/proofs/native-auth/core/src/lib.rs)。旧 `Tx(fail)=Nop` 与
reads→writes normal form 是规格/简化模型；当前失败可能收费并消耗 nonce，
必须显式建模，不能声称旧规格自动证明所有 NOV 业务。

## 3. 实施顺序与每阶段出口

| 阶段 | 实际交付 | 必须保留的出口证据 |
| --- | --- | --- |
| S1：显式业务效应与条件交换 | 真实 Transfer 计划表达状态前提、依赖与可交换效应；AOEM 执行计算及归并。先消除可证明的纯 credit 假冲突，再扩展，不先改交易顺序或经济规则 | 串行参考逐根/余额/nonce/费用/成功失败回执一致；真回调重叠；共享热点、边界溢出、失败后状态及候选隔离 |
| S2：批量增量回执与持久化 | 按批次处理必要状态与回执增量，收敛重复存储交接/回读；保留同一 AOEM 权威根和可恢复完成协议 | 随历史增长不回退为整账本物化；提交/未知结果/损坏拒绝/重启恢复；区分实际写量与逻辑 live 状态量 |
| S3：网络、执行、证明、最终性流水线 | 真实有界阶段和回压，接入/计算不阻塞必要共识进展；固定已签证明重发与新签票权限分离，提交仍确定有序 | 同路径持续签名负载的四节点最终性、失败率、TPS、P95/P99、状态增长、恢复；旧回调/旧父/换轮迟到结果不得授权新状态 |
| S4：真实业务证明契约 | 定义可信父根、业务程序/语义版本、交易承诺、完整状态效应及公开输出；复用成熟证明能力，接入惰性/批量/价值分级验证规则 | 错父根、错业务、缺/坏证明拒绝；非证明路径明确标注；证明生成、验证、尺寸及最终确认分开计量 |

S4 的声明与接口应在 S1 开始时同时核对，不能等宿主实现再次固化后才发现
无法证明；完整证明实现按阶段推进。任何新证明强制策略、主网参数或协议
切换须明确版本和用户决定，不以本计划暗自启用。

### 已验收第一刀：只收不支账户的纯 credit 条件交换

- 从完整候选效应识别该资产的批内只收不支账户；它不得被其他交易扣款、
  作为 payer 或有其他依赖当前余额的效应。账户身份保留原 20/32 字节区分。
- 用 `checked` 算术确认“父余额 + 整批可能入账上界”处于 u128 范围；失败
  交易可能不入账，上界保守成立才允许去掉纯 credit 引起的假依赖。
  条件不成立或效应未知则保留原冲突/参考路径，不能溢出截断或静默换语义。
- debit、费用、nonce 和其他真实依赖仍按原规则；组件计算和按原交易序号
  的 credit 归并都由 AOEM 回调执行，不以 Host 预先算出的最终写集冒充计算。
- 逐项前提、全局费用结算导致的失败/失效及有界重算维持原规则；业务失败
  不是基础设施错误，nonce/费用效果不能被一律清零。
- 复用现有串行参考、真实候选、混合成功/失败及四进程夹具；补多付款方向
  同一收款方、收款后再花的排除条件、自转、u128 余量和手续费边界。
  观察真实任务重叠，不用 sleep/barrier 造峰，不用算子微基准替代主链验收。

这一刀只是 S1 的主链接入第一段，不等于通用 OCCC、GPU 同构、S2–S4、
高吞吐最终性或整个活动目标完成。数百万内核/专用操作每秒不是本刀承诺的
主链 TPS；不擅自填写用户未确定的生产量化目标。

### 已验收 S2 第二片：每笔 typed record effects

- 不把 3 次整稀疏 Store 编码改成 2 次缓存，而是每笔不再整视图编码：用
  已授权路径和已加载 raw records 初始化候选内 effect journal，直接对
  固定标量、本笔账户/nonce、失败键、当前及实际淘汰 trace 做 typed 投影。
  保留 u128 原始编码、None/零值/结构标记的区别，不经 `serde_json::Value`。
- 原费用/业务 helpers 不改。分“业务+nonce”和“回执收尾”两阶段产生
  `RawPathChange`，原业务 delta/count/root/seal 以及回执根顺序保持不变；
  receipt/mirror/last_updated 的物理变化不能误入业务状态 delta。
- 批末保留 `sparse.changed_records()` 独立完整核对一次，与 journal 的
  净 patch 逐项相等；漏记、额外写或访问越权必须失败，候选不得发布。
- 使用旧三次编码算法作为 test-only oracle，逐笔对照业务 delta、根、
  seal、完整回执/mirror；覆盖收费失败、业务失败、自转、零金额建账户、
  signer nonce、日窗、满 trace/journal 窗口、u128 边界。验证每笔整编码
  调用为 0，再复跑候选恢复和同路径四进程负载，不能仅以计数当 TPS。
- journal 和 trace order 目前仍是数组记录，变化时仍需编码该条数组；
  本刀不暗改 codec，也不宣称已解决状态树全部多版本放大或 S3 流水线。

### 未验收配套草稿：候选输出一次准备与耐久收口

- 已从代码确认同一次首次输出在 prepare、persist 前、persist 后和最终
  readback 反复调用 delta 验证，实际重建 physical/state/receipt 三树，
  不是只检查摘要。以真实负载计量改动前后，不据当前 TPS 猜测耗时占比。
- 将已验证 document 与对应 updates 封装为私有只读 packet；不能把可变
  文档和可替换 updates 分开传入后直接信任“以前验过”。已有替换 updates
  拒绝用例必须保留；旧接口、旧格式和恢复调用不暗自降级为信任缓存。
- 首次正常写入复用同一已绑定准备结果，保留实际节点/分片写前写后检查、
  内容冲突检查、未知结果锁和 completion。不能把 staged/prewrite 缓存当
  成耐久回读证据，不能提前标记完成。
- 保留 **OutputWritten checkpoint 之后**的完整输出读回；恢复、重开、
  未知提交结果和旧 reservation 仍独立验证。不得用 checkpoint 前的验证
  替代其后的持久事实，也不得为兼容回放重新执行一次业务。
- 逐笔 state 根、semantic delta/count/seal、完整 receipt 与三树 codec 不变；
  必须复跑篡改/四阶段恢复/旧格式回放、串行对照和同路径四进程负载。
  本刀不解决 journal 多版本、S3 全流水线或 S4 业务证明，也不以此结束目标。

## 4. 保留、分工与验收纪律

保留真实 AOEM 通用 graph/compute、密码算子、NovoRUDP/Overlay、鉴权、
增量状态树、候选隔离、费用守恒、持久投票锁、QC/祖先域绑定和恢复成果。
旧仓的单验证者 smoke、模拟成功协调器、未接通 GPU backend 不原样恢复。
必要时重做语义计划与证明/共识接口，但不能跳过安全不变量换取性能。

- A：在 SUPERVM main 独占 `native_transfer*`、候选/fresh 生命周期与通用
  执行适配的本轮集成；子代理按明确文件范围工作。重叠的 27 文件试验单独
  审查，未经本轮验证不顺带提交。AOEM 如真缺通用 ABI，先记录需求并确认
  该仓授权，不能借本计划修改兄弟仓库。
- B：拉取并确认后认领隐私/PQ 独立组件。经典隐私先做真实钱包收款再花、
  守恒与防双花；ML-DSA 沿用用户已接受的标准正确性能取舍。共享 wire、
  鉴权、候选、证明、封印、Cargo/绑定由 A 统一交接；不假定 B 已在线。
- 隐私与 PQ 不从目标删除：组件最终必须接同一主链。经典隐私明确非 PQ，
  ML-DSA 外层签名不改变其承诺/证明假设；主网参数和强制/混合方案不自选。
- 每阶段先证明语义/安全再测真实路径；使用既有串行参考、混合失败、QC、
  持久恢复与连续负载门。记录提交/二进制、硬件、拓扑、负载、冲突、账本
  规模与原始结果；本机四进程不是实体四机，诊断开启不是正式性能对照。
- 只提交并及时推送已验证、明确负责的改动，保留失败报告。没有完成三条
  产品主线前，不称完整高性能 Web3 主网；部署/正式创世/密钥仍另需授权。
