# 真实 AOEM 主节点 prepare QC 联调 V1

这一步验证了：同一份候选由真实 AOEM 独立执行并落盘后，启动正式
`novovm-node` 封印服务，经 WSS / Product Overlay 收发投票，可在四名固定
验证者中仅三名在线、初始负责人离线时取得并保存 **3/4 prepare QC**。

这不是主网最终确认。`proof_sealed/chain_canonical/safe/finalized` 仍为 false。
本测试不增加共识算法或修改 AOEM 内核，只把既有组件放到真实主进程中联调，
并修复联调暴露的 Windows 交付日志路径问题。

## 实际覆盖

- 一个源节点从原生签名交易生成候选；三个新节点只取得候选输入计划，使用独立
  状态目录和 namespace 真实调用 AOEM，完整区块及状态/回执/执行证据一致。
- 四个固定等权验证者，签名身份与传输身份分离。全过程保留相同四人名单。
- 明确不启动初始负责人；先启动剩余两人：有界退出报未取得 QC，数据库没有 QC。
- 再启动其余三人：真实时钟触发换轮，主循环自行处理提案与投票；没有测试代码
  代签、伪造执行事实或直接调用轮次驱动器推进状态。
- 每台活动节点都正常退出，并从 RocksDB 读回 QC，核验签名数/权重均为 3、
  门槛满足且绑定正确候选。执行账本仍与原未封印区块一致。
- 三台节点重新启动，读回同一 QC 集合与未封印账本；不删除签名锁或复制数据库。

网络为本机回环 WSS：签名 bootstrap、独立 relay 身份、显式测试 CA 校验及
peer E2E 加密。测试使用一次性 fixture 身份，不是生产密钥分发方案。
Relay 在测试进程的独立线程运行，三个签名服务在独立主节点进程运行。

## 如何重复测试

正式 WSS 发现契约要求 443。该测试需要独占 `127.0.0.2:443`，因此默认标记
`ignored`，不把普通 CI 通过视为执行了它，也不自动关停占用端口的服务：

```sh
cargo test -p novovm-node --test native_candidate_node_cli real_aoem_main_nodes -- --ignored --test-threads=1
```

绑定失败即失败；没有改成明文传输、关闭证书验证或放宽 relay 发现规则。
不要与本测试的另一个实例并发运行。Linux 还需操作者准备低端口绑定权限；
本次 Windows 结果不代表 Linux 实机已签收。

每个节点的启动输出、错误输出及周期进度文件保留在
`artifacts/audit/candidate-node-processes/` 的独立运行目录。
最终 relay 目录下的 `acceptance.json` 包含节点证据路径、离线负责人、真实 QC
和边界声明；不包含私钥。断言失败时不会生成本次通过报告。

测试的 tick 数与换轮超时只是有限运行预算，不是出块间隔或吞吐率承诺。
4 秒换轮的试跑曾通过，但复跑出现反复超时、各节点处在不同轮次且未取得 QC，
另有一次长 tick 预算触发外部测试超时；这些失败均保留，不能宣称短换轮稳定。
后续采用主节点默认 250ms tick、15 秒换轮进行验收，签名/持久化门槛不变。
不能把这个配置下的通过结果推广到任意时序、硬件或负载。

2026-09-26 本机该配置完整通过（159.89 秒），生成验收报告。另有默认候选
CLI 3/3、封印服务 22/22、封印启动 CLI 4/4、真实 RocksDB 路径回归 1/1 通过；
node/novovmctl 全目标 Clippy 与格式检查通过。完整主线门禁本次未重跑，既有
本机 EVM reorg 测试问题不在本切片修复范围内。

## Windows 修复

相对配置路径以配置目录解析后会得到 Windows `\\?\` 路径。RocksDB 随后拼接
`/LOG` 会打开失败。复用已有封印存储的原生路径转换，统一处理交付日志的
数据库路径；仍保留真实路径解析和存储隔离检查，不要求跨机器目录同名。
回归测试直接按解析出的路径创建、写入并重新打开 RocksDB，不只比较路径字符串。
