# V3 决策确认：验证与本地持久签名，未在线启用

## 解决的协议定义问题

V2 target 绑定完整 subject_hash 和 proposal_hash，其中包含投票轮次。
V2 signer/height 槽只允许一个不可变目标。因此 V2 不同轮次的确认票不能相加；
收票、重传或超时参数不能解除这个限制。V1/V2 语义和持久安全锁保持不变。

V3 新增独立签名域、票据 schema、凭证 schema 与纯验证 API。
`decision_target_v3` 先完整验证 prepare QC，再仅将 subject.round 规范为 0，
重算 subject_hash，最后用 V3 domain 进行哈希。规范化的 subject 不是新 proposal，
不写盘、不导入 admission，也不赋予 round 0 签名权限。

目标排除投票轮次、提议者/提议签名与 prepare 签名子集；仍绑定原 subject 的
所有其他字段，包括链域、创世、epoch、验证者集合、height、slot、时间戳、
候选身份、父块、**父 justify QC**、执行上下文、协议配置、交易/状态/回执根、
DA 承诺及 AOEM 证据。父 QC 不是可以随换轮丢弃的字段。

因此，同一完整决策的 **V3** 签名可以使用不同轮次的有效 QC 作为验证见证。
这不是把现有 V2 票混在一起。旧签名即使改 schema/target 也不能通过 V3 签名域。
凭证中的 prepare.round 仅为见证轮次，不代表所有签名者参与过该轮。

## 安全边界与后续必须实现的内容

已有目标计算、票验证、按唯一成员权重组装/验证凭证，以及显式本地调用的
`sign_local_decision_vote_v3`，以及完整凭证的持久归档/读回 API。已有 V3 消息编解码与认证验证，尚无在线 V3 收票调度、配置开关或
V2 自动升级。基础验证测试中的裸签名 helper 仅在测试编译。
凭证验证成功不代表 DA 可用、本地执行已验证、leader/new-view 合法、父块 finalized，
更不代表 ledger/AOEM 已晋升。所有现有在线流程不变。

本地持久签名锁实现“一身份/链/epoch/高度只能确认一个决策”，与 V1/V2 共用
不可变 signer/height 槽，schema 不同即拒绝。首次签名要求本地候选执行匹配、
固定验证者集合、原样持久 QC/提议/索引、有效且当前的 new-view admission、
没有本轮 timeout，并检查已有 QC 不包含另一决策。已有旧版确认凭证的高度拒绝签名。

签名、原始见证引用、内容哈希标记和 round/height 安全锁在同一同步 batch 保存，
读回成功后才返回。已有签名只原样重放；换轮重放验证新见证和原始见证，检查原始
轮次的安全锁，而不是伪造新轮签名或补写新轮锁。旧轮已 timeout 不禁止原样重放；
已 timeout 且未签过的节点不能在该轮新签。marker、原始 QC 或任一安全锁丢失
均拒绝重放。未承诺检测整个数据库回滚、锁与 marker 同时删除或同一密钥在另一套
数据库中重新运行；运营上仍禁止同一身份多实例签名、清库或复制密钥另开签名库。

在固定权重集合与小于 1/3 拜占庭权重假设下，严格超过 2/3 的两个不同决策法定集合
必然有诚实成员交集；本地锁并不等于在线换轮与最终性协议完成。

后续顺序：接入有界在线消息与超时恢复 →
分区/重启/冲突候选验收 → 最终祖先和状态晋升验证。
保留不可变候选锁仍可能造成冲突候选之间的停滞；本刀只消除“同一决策因轮次不同
而不能共享 V3 确认”的定义障碍，不证明任意分叉下的活性。

## 本刀测试

- 同一决策的三个不同轮次/提议者的测试签名能组成 V3 凭证，2/4 和重复签名拒绝。
- 逐字段变异：除 round 和派生 subject_hash 外，每个字段改变要么校验拒绝，
  要么产生不同目标；新增未知形态字段使测试失败，要求显式维护。
- 无效 prepare QC、篡改签名、V2 签名重标记以及未知票字段拒绝。
- 合成候选和测试裸签名不等于真实换轮授权、四机网络或主网验收。
- 新增本地持久流程测试：合法 new-view 后跨轮原样重放且数据库零变更，
  不同轮首次产生的真实本地 V3 签名组成凭证；重启、版本双向隔离、timeout
  禁止新签以及五类关键记录丢失拒绝。测试仍使用合成执行候选与隔离临时数据库。

AOEM、现有节点/聊天服务和操作员数据未修改。无真实余额迁移要求。

## 完整凭证持久归档

`persist_local_verified_decision_certificate_v3` 要求足额有效 V3 凭证、匹配的
本地执行候选、固定验证者集合，以及已持久化的精确 QC、proposal、索引和
new-view admission。已有 QC 清单中出现不同决策时拒绝归档。

归档与 V1/V2 共用 chain/epoch/height 凭证槽，跨版本读取或覆盖均报错。
凭证与 certificate_hash 标记在同一同步 batch 保存并读回验证；同一决策的
其他轮次/子集凭证返回 false，保留第一次归档的原始证据。并发归档由现有写锁串行化。

`load_decision_certificate_by_height_v3` 验证槽身份、固定集合、全部签名及权重、
精确原始 QC/提议/索引/admission 和哈希标记。只有凭证与 marker 都不存在才返回
None；只丢失其中一项、篡改、错高度或原始 QC 丢失均报错，不能用重新归档掩盖。
签名入口同样检查该归档：已有完整凭证则停止继续签名/签名重放，调用方应发送完整
凭证；损坏归档也不允许继续签名。该入口不把 V2 自动转为 V3。

读回表示历史确认事实，不重新声称当前 DA、执行状态晋升或 finalized。
不检测整个数据库回滚或凭证与 marker 同时删除，不把正常重启等同物理断电验证。

测试覆盖跨轮等价凭证不覆盖、并发首写、重启读回、记录/marker/QC 丢失、哈希或签名
篡改、错高度、旧版凭证保护和不匹配本地执行拒绝；ledger head 和最终性保持不变。
仍为合成候选、本地隔离数据库测试，实体网络与长跑未在本刀执行。

## V3 有界消息格式与认证验证

在现有 `NOVSRW01` 帧尾部扩展 kind 9（DecisionVoteV3）、10（DecisionCertificateV3），
旧 1–8 编号及其序列化次序不变。旧接收器不认识新 kind 时拒绝，不静默降级。
外层 framing 仍为 v1，不代表内层决策签名也使用 v1。

单票携带 proposal、prepare QC、V3 vote 和必要的 new-view 证据；完整凭证携带
proposal、V3 certificate 和 new-view 证据。前者要求认证发送者正是票的签名者，
后者允许固定成员转发，但必须验证全部真实签名、法定权重及见证/提议的精确绑定。
消息中的 round 是见证轮次，不是要求 V3 签名重新绑定该轮次。

沿用 192 KiB 帧上限、序列/嵌套/字符串限制、128 KiB new-view 预算、规范编码和
完整帧校验。非零轮缺 admission 证据、非指定 leader、错误链域/高度、错误发送者、
不足额凭证或伪装为 V2 的消息均拒绝。编解码不签名、不落盘、不改变 tracker。

当前在线 round driver 明确拒绝 V3，原有 V2 模式保持不变。**本刀不是在线激活或
收票调度完成**；后续仍需显式 V3 模式绑定、有界收票、跨轮恢复和服务生命周期集成。
测试覆盖 round 0/1 编解码、旧轮决策票携带新轮合法见证、来源/高度/帧长/签名/
不足额/new-view 缺失拒绝，以及在线驱动拒绝后状态不变；未进行 V3 实际 WSS 多节点运行。
