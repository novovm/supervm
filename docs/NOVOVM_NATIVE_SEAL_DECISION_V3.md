# V3 决策确认基础：仅验证原语，未启用

## 解决的协议定义问题

V2 target 绑定完整 subject_hash 和 proposal_hash，其中包含投票轮次。
V2 signer/height 槽只允许一个不可变目标。因此 V2 不同轮次的确认票不能相加；
收票、重传或超时参数不能解除这个限制。V1/V2 语义和持久安全锁保持不变。

V3 新增独立签名域、票据 schema、凭证 schema 与纯验证 API。
`decision_target_v3` 先完整验证 prepare QC，再仅将 subject.round 规范为 0，
重算 subject_hash，最后用 V3 domain 进行哈希。规范化的 subject 不是新 proposal，
不写盘、不导入 admission，也不赋予 round 0 签名权限。

目标排除投票轮次、提议者/提议签名与 prepare 签名子集；仍绑定原 subject 的
所有其他字段，包括链域、创世、epoch、验证者集合、height、slot、时间戳、
候选身份、父块、**父 justify QC**、执行上下文、协议配置、交易/状态/回执根、
DA 承诺及 AOEM 证据。父 QC 不是可以随换轮丢弃的字段。

因此，同一完整决策的 **V3** 签名可以使用不同轮次的有效 QC 作为验证见证。
这不是把现有 V2 票混在一起。旧签名即使改 schema/target 也不能通过 V3 签名域。
凭证中的 prepare.round 仅为见证轮次，不代表所有签名者参与过该轮。

## 安全边界与后续必须实现的内容

当前只有目标计算、票验证、按唯一成员权重组装/验证凭证，没有生产签名 API、
存储 API、网络消息、配置开关或 V2 自动升级。测试中的裸签名 helper 仅在测试编译。
凭证验证成功不代表 DA 可用、本地执行已验证、leader/new-view 合法、父块 finalized，
更不代表 ledger/AOEM 已晋升。所有现有在线流程不变。

安全性所需的“一身份/链/epoch/高度只能确认一个决策”仍待实现持久签名锁：
必须与旧版本共用防重复确认边界，拒绝跨版本重解释；只能原样重放同一决策签名，
不得通过数据库更换、轮次变化或进程重启获得第二个决策的签名许可。
在固定权重集合与小于 1/3 拜占庭权重假设下，严格超过 2/3 的两个不同决策法定集合
必然有诚实成员交集；但本刀没有实现该持久签名约束，不能据此宣布在线安全协议完成。

后续顺序：持久 signer/height 决策锁与版本隔离 → 本地执行/DA/父依赖/换轮证据
验证后的签名许可 → 接入有界在线消息与超时恢复 → 分区/重启/冲突候选验收。
保留不可变候选锁仍可能造成冲突候选之间的停滞；本刀只消除“同一决策因轮次不同
而不能共享 V3 确认”的定义障碍，不证明任意分叉下的活性。

## 本刀测试

- 同一决策的三个不同轮次/提议者的测试签名能组成 V3 凭证，2/4 和重复签名拒绝。
- 逐字段变异：除 round 和派生 subject_hash 外，每个字段改变要么校验拒绝，
  要么产生不同目标；新增未知形态字段使测试失败，要求显式维护。
- 无效 prepare QC、篡改签名、V2 签名重标记以及未知票字段拒绝。
- 合成候选和测试裸签名不等于真实换轮授权、四机网络或主网验收。

AOEM、现有节点/聊天服务和操作员数据未修改。无真实余额迁移要求。
