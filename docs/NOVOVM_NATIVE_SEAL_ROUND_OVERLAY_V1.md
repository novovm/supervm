后续进展（2026-09-22）：[原生候选共识服务：主节点接入 V1](NOVOVM_NATIVE_SEAL_SERVICE_V1.md)
已补上默认关闭的主节点配置、独立签名密钥入口、来源预算和主循环装配。
下文保留本切片交付时的验证范围；“尚未装配”的历史描述不代表最新代码状态。
真实 AOEM 完整进程与实体多机验收、最终确认和连续出块仍未完成。

这次补的是：**把上一刀的“负责人缺席后换人接手”流程，接到节点实际使用的
Product Overlay 加密通信上。** 不再只在测试里直接递交 Rust 对象，消息必须
编码、经过 WSS relay 和节点之间的认证加密通道，再解码、核对来源和证据。

它是显式启用的库组件，不会自动改变已运行的节点、聊天服务或手机行为。
生产 `novovm-node` 尚未装配这个组件；下面的本机网络验证也不是部署操作。

## 交付范围

- 独立的 `NOVSRW01` 消息协议，传输超时票、超时证书、换轮观察、提案、准备票
  和 prepare QC；非零轮提案携带完整换轮证据。旧 `NOVSLW01` 仍只接受第 0 轮。
- `NovNativeSealRoundOverlayV1` 把固定高度的驱动器与 Duplex Overlay 连接起来。
  必须匹配本地链、签名者对应的传输身份和固定验证者完整 peer 集。
- 收到的证据绑定完整帧哈希、payload 哈希、发送者、接收者和 delivery ID。
  直接签名消息的来源必须就是签名者；聚合证书可由固定验证者转发，但转发者
  不会凭空增加签名权重。
- 只有本地主循环调用 `poll` 并提供本机密钥才会产生本地签名。收包只核验、
  收集证据；本地候选匹配、持久签名锁、新轮准入和 QC 恢复仍由已有规则控制。
- 按接收节点分别排队，失败不算成功；轮转游标避免容量很小的队列只服务前排。
  相同证据成功入队后至少隔 250ms 再尝试。**250ms 是重发节流，不是出块周期。**

完整 wire 最多 192 KiB，包含 112 字节头部与校验和开销。解码先限定长度、
版本、链域和来源，再解析；动态序列最多 64 项、字符串最多 4096 字节、递归
深度最多 32，限制在分配向量之前检查。必须是唯一规范编码，不接受尾随数据、
非最短整数或头部与正文不一致的内容。NVC 收包和本地准入共用 128 KiB 上限。

每轮每个来源最多缓存 8 个已经验证的完整消息哈希，避免重发反复核验签名。
缓存绑定认证来源，换轮清空，未来轮消息不会被标记成已经处理。发送端缓存也
只保留当前输出，最多 8 个消息乘 63 个接收节点；没有无限增长的历史队列。
这不是完整的恶意流量防护，生产循环还需要来源级计算预算和限速。

## 调用纪律

```text
本地已执行候选 + 固定 authority + 自己的 signer
  → open 单高度驱动器
  → attach 到匹配的 Duplex Overlay
  → 主循环分发认证 Inbound 给 ingest
  → 主循环按节奏调用 poll，重发必要证据
  → 得到 prepare QC；最终性标志仍为 false
```

`ingest` 只能接收真实 Overlay 产生的认证事件，不能把 RPC 请求里的 peer ID
填进公开结构体就当作认证。普通远端错误应记录、拒绝该消息并继续处理其他事件，
不能用一个未经分类的 `?` 把整个服务退出；本地 `poll` 错误才锁定为 `Halted`。
`poll` 的返回数量是**本地队列接收数量**，不是远端收到、持久化、投票或最终确认数量。

组件不自行 drain 共享网络事件，避免吞掉交易、ACK 或监控事件。未知候选不自动
下载、执行或信任；最高 QC 缺少要求的本地记录时仍拒绝推进，不绕过候选锁。

**不发送 `JournalPersisted` ACK。** 当前远端消息缓存是内存状态；把它说成已经
持久保存会导致对端错误停止重发。重启后需要重新取得远端证据，本地已经持久化
的签名、轮次、候选准入和 prepare QC 继续通过原来的恢复检查。
