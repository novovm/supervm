## 权限与撤权

| 主体 | 过渡期 | 到期／封盘后 |
| --- | --- | --- |
| 创始人过渡钥 | 仅已批准能力清单中的对象、范围、有效期；不得绕过最终性或处置他人资产 | 到期立即拒绝该能力；封盘持久撤销全部创始人特有链级能力，不允许旧钥、更新根、备份或升级重挂 |
| 现役验证者 | 仅依当期集合、权重和用途签共识；交接授权必须签专用对象 | 退役权重在新 epoch 为零；旧钥只证明旧历史，不签新状态；同一运营者合法入选时只有普通现役权力 |
| 后继验证者 | 提交独立用途持钥证明和就绪签名，不提前参与共识 | 仅从确定激活边界开始，使用已承诺的新集合和套件 |
| 普通个人资产钥 | 只处置自己资产；余额和 nonce 继续沿原规则 | 不因角色撤权而冻结个人资产；禁止复用为创始人能力钥 |
| 国库、客户义务、服务／发布钥 | 分账，按各自获批授权执行；发布与设施所用钥不授予共识权 | 公开资金和既有义务按批准的无单方控制规则继续；不能以暂停设施或下架软件替代链级撤权 |

## 拟议状态转移

1. **承诺。** 正式创世承诺固定宪章版本及不可突破约束，持久状态记录现役集合、协议与套件、能力及撤权、单调生效序号和封盘位。计划绑定域、创世/宪章、同一已终局父状态及根、原/新 epoch 和集合承诺、激活边界、套件、过渡策略版本和用途标签。授权签名覆盖规范编码的完整计划；不能借用普通 QC 签名、其他链/高度签名、发布签名或恢复票。
2. **资格与切换。** 拟议采用现役集合对计划授权、后继集合单独证明持钥与就绪，再以原规则终局确认计划。独立的授权/就绪门槛、资格、权重来源、利益冲突、审查及延时、激活窗口和取消规则均待正式批准。新集合成员、权重总和、门槛范围和编码须先验证；本测试模型仅接受给定的有效夹具。激活位置只准一个集合签业务共识；状态、签票历史、旧历史验签映射与集合切换须写入同一可恢复边界。分区或低权重时保持安全停等，恢复后仅沿同一已确认父历史追赶；不得临时降门槛或令旧集合接管。迟到节点可验证并追上已生效转换，不在较晚任意位置重新激活。
3. **一次性封盘。** 已批准的授权、实际退出/移交证据（含未结义务、发布和设施依赖）、无未决冲突迁移及同一规范链的最终性都齐备，再原子写入 sealed 标志和撤权清单。重复封盘、旧钥恢复权限、降低宪章版本或加载回退后恢复权力一律拒绝。灾备按独立已终局检查点验真，不得将较早备份当当前权力根。
4. **合法密码迁移。** 原已批准规则及旧套件验证计划，后继以新套件证明持钥且通过就绪和同一激活门禁；激活前禁用后继共识，激活后禁止用旧套件对新位置验签。旧历史继续按当期套件验真，不变创世域、已终局历史、原签票约束或封盘撤权状态。不支持新套件的节点安全停等，不降级、跳过验签或用旧二进制追随不同状态。

后续实现验收须另接现有 QC、批准的专用授权编码和原持久化所有者，用真正签名的隔离向量验证错误域/套件、双集合冲突、激活写入中断、封盘后冷恢复和旧二进制拒绝。未验证这些能力前不宣布正式封盘或自治通过。
