日期：2026-10-25。审阅输入：`66e652d2`；同时观察本机尚未提交的共识 ML-DSA-65、固定供应与守恒改动。

## 1. 用户目标与一次闭环的含义

不再先发布旧经济规则，再整体更换。使用同一套 NOVOVM/NOVONET 程序、原生入口、
经济约束、服务管理和恢复机制，完成创世分配、用途锁定、授权花费、真实服务报酬到账、
再消费及故障恢复，并进行一个月全流程演练。内部实现可以分提交，退出标准不能拆成孤立接口。

演练可以使用完整、经批准的分配与释放配置。2026-10-26 用户进一步明确：当前仅自用，
资产、钱包和界面统一称 **NOV**，不要求额外“测试 NOV”标注，不另造测试币或经济规则。
内部部署记录仍注明未正式发布及正式发布前会重创世，用于保持链域、签票和资产历史边界。
演练通过后，在明确正式发布授权下，用新的链/签名域和最终批准清单重新创世；
不是切换另一套经济实现，也不把旧域余额或授权自动带入新域。

## 4. 同一资金只计一次：拟议状态关系

采用**账户背书的限制记录**：NOV 仍保存在原资产余额叶；锁定、任务预留、应付是该余额的
受限部分及其义务，不复制一份可花“服务币”。这是拟议状态表达，不是新增 API 已实现。

对同一资金来源使用互斥分类：`账面余额 = 可用 + 尚未承诺的受限份额 + 活动预留 + 已履约待付`。
若用途锁包含某任务预留，预留须从其“尚未承诺”部分转出，不能又减总锁又减预留。
另按资金批次保留累计已支付/已退款记录，用于生命周期核对，不再把历史支付加回当前供应。
现有费用国库持有量按原 owner 计一次；reserve/fee/risk 分桶和累计结算计数不是新增资产。

| 动作 | 同一原子状态转换必须包含 |
| --- | --- |
| 创世/用途锁 | 已发行余额、用途/受益人/控制策略、唯一锁批次、批准释放表；未释放份额不能被普通转账绕过 |
| 释放 | 已批准条件满足后减少受限份额，增加可用份额；不改变账面总额；重复、换钥、恢复不提前或重复释放 |
| 接单预留 | 精确父状态下检查可用余额及独立支出授权，冻结最大成本，绑定链域、报价/策略、付款方、收款方、任务、期限及唯一义务 |
| 履约核销 | 合格且未核销增量把活动预留转成应付；初始保管承诺不能直接核销未来 TTL；不得增加任务已批准最大成本 |
| 具体到账 | 核销该应付并实际扣付款余额、增指定 UCA 资产余额及明确费用，生成原生回执；幂等标记与资金变化一起发布 |
| 释放/退款 | 仅按原关闭/最终核销或争议窗口规则释放未赚取余量；迟到合法索赔与退款互斥，不用客户端超时提前解冻 |

金额与授权要分别冻结：多个任务不能同时消费同一余额，亦不能同时占用同一授权预算。
预留的最大成本与最终实际成本只能扣一次；未使用授权额度仅按原义务释放回**原授权**，
不能转入新授权、扩大限额或复活已撤销权限。撤销/过期阻止新任务，不抹掉旧合法应付。
余额、锁/预留、应付、授权额度、nonce、去重序号与费用均取同一父状态并进入同一候选写集。

UCA 内零钱与储蓄继续分权限，默认外部收款/服务收入进入合法储蓄映射；收入不自动补足手机
额度。KEY ONE 主控不要求手机追加资产审批签名；其管理/直接支出用途合同仍需统一，不能
删掉密钥分离检查来冒充完成。这里的手机 A/B 与部署机器 A/B 是不同命名空间。
当前初始化每个唯一 UCA 只接受一个 `asset_account`，原捕获记录也只有一份绑定；
不能将“同账户多授权”的已有测试当作“同 UCA 储蓄/零钱资产隔离”已完成。应复用原 UCA
多资产绑定模型扩展这份可信投影、签名意图和查询，不新增 UCA 身份或第二份余额库。

## 5. 不冻结比例，也能完成机制与完整闭环

建议以**显式批准的版本化政策**作为编译输入，不设置 50% 或 80/10/10 默认值。
政策必须明确各输出角色、受益账户、计价基数、总成本/净收、费用承担、舍入余数和适用事件；
报价绑定其承诺。缺少有效政策即拒绝新义务，不能把“零平台费”或“提供者全得”当隐式政策。
已接受任务沿原政策完成，不因后来提价、换月或治理升级重新分账。

机制验收可使用明确隔离的、非部署批准的测试向量，验证不同分配参数下同一程序守恒，
而实际一个月演练必须先取得自己的完整批准配置。最终正式分配可以与演练同形，具体金额、
受益人及控制关系需要批准；不用为演练另造经济执行模式，也不以测试向量授权真实资金。

首个服务证据闭环选原临时密文保管/领取：有资金预留 → 真实 Put/Fetch/Consume 及约定阶段证据
→ 去重核销 → 指定 UCA 到账 → 收款人合法再花费。服务身份与收款权限必须有可信绑定；
现有 Ed25519 StoreReceipt 可作为历史/通信阶段证据，不能直接冒充首发 ML-DSA-65 的完整
经济履约授权。复用同一规范密码门面补版本化服务证据适配，手机机器消费，不重复实现。
自费关联测试可以检验付款闭环，但不证明公共补助资格或独立服务；建设补助另按采购合同验收。

需共同评审而不能代定的选择：

- 释放按确定日历表或明确事件触发；两者都须明确累计整数额度、原始锚点与权限，不以节点本地时钟裁决。
- 服务报价采用总价含费或承诺净收；采用哪一种、结算执行费由谁承担须事前批准。
- 履约证据的核验主体、时间/累计序号、关闭依据与争议窗口；不能只靠服务者自报给自己付款。
- 新国库决策的多人授权和必要同意，与既有合同的自动核销分开；具体门限/恢复机制不由开发填默认值。
- 隐私资产及查看权限属于首发门槛；透明测试状态仅能验执行，不能把 ML-DSA 或加密传输称为余额隐私。

## 6. 一个月演练的统一退出标准与重创世

同一正式程序必须覆盖：创世总量/用途、未解锁拒付、合法解锁、手机越权/撤销、并发预留耗尽、
逐笔舍入、同一义务重复凭证、部分履约、迟到索赔/退款竞争、具体到账再消费、跨周期未决债务、
预留/核销/发布边界崩溃、单节点离线追赶。余额、限制、应付、授权、nonce、费用、根与回执一致。
CPU 与完整代数计划等价；真实设备联合运行，正式性能计时包含首次等待，并与内容/通信资源成本分别记录。
存活一个月不替代上述故障与隐私验收；正式配置缺项、证明或移动制品缺口仍须如实列出。

演练结束若获准清零，只退役准确识别的测试链账本、创世/运行配置、nonce、签票 journal
和链专用测试钥；先停掉活动写入和自动重启，旧域永久退役，不在空 journal 上沿旧域重新出票。
保留源码、审计/测量证据、合格制品、通信托管、NOVOCHAT 历史、设备/服务/UCA 身份及恢复材料。
混合目录不整删，B 的信箱/Relay/Web 与 C 的手机不随链清零。正式链新域不会自动信任旧资产授权；
保留身份需要经规范重新绑定，而不是清掉通信数据或悄悄复用旧签名域。

最终仍由原初始化编译器根据批准清单与真实公开身份派生最终根/承诺，各机核对同一配置和
各自平台实际制品。批准设计、推送代码、通过 CI 或生成包均不等于已经分配/激活正式 NOV。
