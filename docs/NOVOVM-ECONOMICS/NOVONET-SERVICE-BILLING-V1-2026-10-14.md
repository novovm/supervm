## 1. 产品决定

本轮收入与补助更新以[统一基线第 11–12 节](../../docs_CN/NOVOVM-ECONOMICS/NOVONET-SERVICE-ECONOMICS-BASELINE-2026-10-24.md#11-本轮确认职业化经营与建设补助)为准：职业经营、自费任务允许，公共补助只为事先购买的可验证容量/任务付款，不因订单或回执自动追加。
容量费包含的用量不得再次核销；报价事先说明用户总支出、提供者净收、结算/领取费承担。
免费权益须覆盖范围内最坏履约责任，平均人均成本不证明名额有保障，已授予承诺不得重复占用。
原生精度按[首发契约](NOVOVM-NOV-FIRST-RELEASE-ECONOMIC-CONTRACT-2026-10-24.md)为 9 位，具体整数核销/舍入和实际主链接线仍待验收。

后续首个开发里程碑限定为测试 NOV 的临时密文寄存/领取：真实资金预留 → 合格履约成立应付 → 正确链域具体 UCA 资产账户确认到账 → 按权限转账或再消费；在各阶段重启并验证重复核销、退款及迟到索赔不双付。服务密钥不取得无限支出权。建设补助另验重复容量、关联回流和预算耗尽，未验收不动用资金。本轮只修文档，不启动该里程碑或收费。

- NOV 是唯一付款和结算代币；默认 NOV 预付按量，月套餐只作为未来可选购买方式。USD 仅作
  对照，不自动换币。“通讯额度”是不可转让的资源使用权，不发行可交易 Token，
  不与 NOV 固定兑价。可退预存 NOV 与不可兑现的赠送/套餐额度分别记账。
- NOV 是 NOVOVM 主链原生 Token、NOVONET 唯一主网资产。自由指任何设备可
  无官方批准地提供资源，不代表免费消费。新的 NOVOCHAT 通讯任务必须有 NOV
  支持的有效订阅或预付额度；无额度不能聊天、不能自动转免费路径。已付额度
  不要求钱包随时留有另一笔余额；必要的入网/付款/贡献协商不要求先消费套餐。
- L1–L4 不按层级收过路费，消息不必逐层经过。只支付实际选择、接受报价且
  合格履约的服务者；同类资源同类规则，安装量/在线数不产生报酬。
- 支付确认和批量结算在慢路径。Put/Fetch/Notify/媒体包不逐次查链、不查汇率、
  不动用 UCA 资产根密钥。链上资金未落实时不能把本地余额声明当付款；
  已有资金覆盖的原保管、领取与回执义务继续履行，不因套餐到期中断。

## 2. 付款、额度、服务证据分开

```text
同一 UCA 钱包批准有上限的 NOV 支出
    ↓ 已确认付款 / 受既有结算规则保护的资金预留
按量可用余额 / 可选套餐资源权益 + 有资金支持的服务预算
    ↓ 按提供者、用途、设备划分不可重复花费的预算份额
L1–L4 实际服务 → 计量与有界履约凭证
    ↓ 核验、去重、争议处理、批量结算
具体服务提供者的 UCA 收到 NOV
```

资源剩余、已预留 NOV、待核验报酬、可结算报酬、NOV 已到账分别展示。
StoreReceipt 证明节点接受持久保管承诺，DeviceReceipt 证明设备持久接收，
都不直接证明资产到账；StoreReceipt 也不能单独证明未来整个 TTL 的履约。
本地副本不是可复制到各节点的共同可花余额，赠送额度不是另一个资产账户。

## 3. 自主报价与计量

节点签署自主报价，客户自行选择；签名不是官方定价批准。报价绑定版本、
服务者、服务类别、计量规则、NOV 单价、容量、期限、最大扣款、履约义务、
退款/争议规则和适用费用策略摘要。明确**用户总支出**与**提供者净收入**，
界面展示总扣款上限。过期报价不接受新任务，已接受任务不得追溯提价。

| 服务 | 底层整数计量 | 用户展示 | 边界 |
| --- | --- | --- | --- |
| 文本/图片/文件传输 | 合格有效字节 | 套餐余量、GiB | 重传、环路和自报流量不增加费用/奖励 |
| 临时密文存储 | 字节·秒 | GiB·小时 | 原 TTL、实际履约区间、批准的副本数量；释放后不再计时 |
| 语音视频中继 | 有效中继字节，可附明确容量时间项 | 流量或套餐分钟 | 直连没有第三方媒体中继费；同一成本不能重复计分钟和字节 |
| 群媒体 SFU | 转发字节和明确计算/容量项 | 通话用量 | 不计未执行的转码或 AOEM 计算 |
| 通知/协议维护 | 纳入报价的有界成本 | 不逐条弹单 | 空查询、握手、心跳和通知不是独立挖矿依据 |

GiB = 2^30 字节，GiB·小时 = 2^30 × 3600 字节·秒。密文封装/填充的计量层
在报价固定，不能把应用层和网络层的同一传输重复收费。NOV 使用已批准的9位
精度最小单位整数；累计精确用量后按版本规则舍入，不逐包向上取整。
溢出拒绝、限额检查及守恒必须在实际结算语义中成立。

重试沿用同一服务义务身份，不重复占款。合法补副本可产生独立节点义务，
但先占用原批准的副本预算，不重置 Message ID 或 TTL，不因多跳自动涨价。
默认发送方预算覆盖投递、必要回执和保管，不让陌生人通过发消息自动扣接收方
钱包；接收方仍决定谁可寄存。额外长期保留等服务由实际购买者另行选择。

## 4. 多节点和多设备预算

首版建议使用限定提供者/用途、由实际资金支持的预算份额，接入原结算所有者：

1. 钱包批准总上限；付款/资金锁定达到约定确定性后才建立可消费预算。
2. 每份绑定提供者、消费设备、用途、计量版本及上限；所有并发份额之和不超
   可支出资金。离线客户端不能自行复制、分裂或重新分配尚未关闭的份额。
3. 提供者接单前核验份额和资源，原子预留最大成本；负责该份额的状态所有者
   持久保存累计用量/序号，重复请求、重启和丢 ACK 不得重复占款或结算。
4. 有界累计凭证或去重义务凭证只核销未结算增量。付款、预留、履约待付、
   结算、释放和退款分别幂等，不能重启回滚余额或把同一笔钱多次分账。
5. 释放/改派未决份额前需要可靠的关闭/最终核销依据，或等待协议的结算及争议
   窗口结束。手机超时或时间到期不能立即全额退回再花，避免原服务者迟到索赔双花。

预算守恒（同一口径，计入所有未决负债）：

`已最终入资 = 未分配 + 活动预留 + 已履约待结算 + 已结算 + 已退回`

这还不是已实现的离线防双花。正式接线须选定并验证原 NOVOVM 账本中的资金
预留/通道状态表达；不能用普通签名额度或新的官方发放服务器替代该保证。
没有剩余额度时停止新收费通讯义务，不转免费路径、不暗扣、不降隐私。
套餐到期、关闭贡献或结算暂不可达，不得抹掉已接受的原 TTL/领取/回执义务；
接单时需覆盖这些成本，不能以重新购买套餐为旧消息领取前提。

## 5. 套餐与协议分账：只花一次同一笔钱

以下是 2026-10-14 对旧组件的源码核对，**不是 2026-10-24 首发分账规则**：

- [types.rs](../../crates/novovm-consensus/src/types.rs) 默认服务分账：
  provider 4000 基点、burn 1000 基点、余下国库；不是已批准套餐或创世费率。
- [token_runtime.rs](../../crates/novovm-consensus/src/token_runtime.rs)
  `charge_service_fee(payer, amount)` 向底层传入 `[0;32]` 服务标识并返回分账。
- [mainnet_token_impl.rs](../../vendor/web30-core/src/mainnet_token_impl.rs)
  `on_service_fee_paid` 将提供者份额记入 `service_provider_pool`。
  这条已核对调用链未将某份通讯履约凭证核销并直接付款到具体 L4 的 UCA。

上述 burn 路由不能原样启用；只复用其守恒校验/池核算及回归资产，适配到不销毁
且国库、创始人、服务应付分开的当前规则后再验收。具体比例仍待确认。

需要明确订阅收款、资源消费、节点核销各自的经济事件和策略版本；不能每一步
都对同一笔钱重新征收服务费。领取的独立执行成本另列，不重复应用服务分账。

当前预算规则：实际服务收费覆盖提供者报酬、批准的国库/运营份额及明确费用，
各部分总和不得超过该事件可分配资金。旧“每月最低 5 USD 创始人分账”和由它
推导的最低套餐价、100/160 NOV 示例已被替代，不再作为报价要求。

50% 和 80/10/10 仅是比较/候选，不是当前费率。上文 40/10/50 及 burn 字段是
旧组件源码事实，与正式 NOV 不销毁目标有差距；不再把它作为未来默认分账。
充值、收入到账、余额结转不重新抽成；服务分账不能直接覆盖主链其他费用分桶。
国库不是创始人个人钱包，具体提供者应付和到账必须由原账本核销，不只记入池。

充值和已到账收入长期保留，待结算收入不可消费，任务预留不可重复支出；收入
到账不提高消费上限，不跨 UCA 自动调拨。最终未送达不使已履约资源免费；
合法重试不重复收费，未执行部分按原合同和未决索赔窗口释放或退款。

## 6. 奖励和隐私

付费服务报酬、创世补贴和免费试用预算分开。默认L4贡献不是持有/在线奖励；
只有被选择且完成合格服务才进入核验。关联账户全部奖励/返佣/补贴必须合并
核对，付费本身也不能证明服务真实。免费体验需要有界赞助预算，不能按
无限新UCA发可兑现赠金。推广期截至2027年4月底，期间合格新UCA可试用一个
自然月，开通前落实固定资源权益对应的资金、容量和责任提供者。推广截止决定领取资格，
已开始的一个月按原承诺履行；精确截止时区、月周期和赞助总预算在上线前配置，
不在此凭空设定发行额。UCA是全网唯一账户标识，一账户跨设备/重装不重复领取；
账户唯一不等于自然人唯一，创建多个合法UCA仍需受推广总预算/防刷规则约束。
原奖励建议的比例/日程仍未批准。共享开启只获得参与服务机会，实际有效传输、
字节·时间保管、可验证计算或已购买并可核验的预留容量履约后按同一任务预算
分配，不按开关或在线发币。分期空投须预留完整已授予金额，与体验资源分开。

后续内容分发复用L3/L4、UCA和同一NOV计量结算：内容分块、哈希核验、独立副本、
并行获取；按实际合格块交付/保管付费，内容作者报酬与基础设施费用分开。
本轮不新建内容网络；哈希与节点数量都不能替代隐私路由或抗流量关联验收。

节点只获得本次资源必要的服务能力，不默认取得全局钱包地址、联系人图或
明文。各节点服务/结算标识与聊天 Message ID 分开；公开链不放逐条聊天关系、
精确发送时间或可关联信箱对象ID。凭证用域隔离的去重承诺，证据大小/保存期
有界。普通不透明凭证、批量结算不是匿名证明，防关联/ZK仍须独立验证。

## 7. 接线顺序与验收

| 顺序 | 复用位置 | 交付条件 |
| --- | --- | --- |
| 当前 | Application owner、NVMBOX04、原信箱 | 先优化串行等待、冷开运行和L4，不向消息链路插入计费RPC |
| 计量 | 原存储提交、Put/Fetch/Consume、传输统计 | 分项去重、重启恢复，未结算不显示NOV到账 |
| 预算 | 原UCA用途权与NOV结算状态 | 有资金限额、防并发透支/回滚，不另建账户或币 |
| 核销 | 原NOVOVM费用/池/账本 | 明确经济事件、批量去重、具体UCA到账及未决负债核对 |
| 产品 | “我的”和原钱包入口 | 按量余额、可选套餐资源余量、上限和报酬状态，超额须已有用户批准 |

必验：双设备并发耗尽、过期/伪造/撤销报价、重复Put、丢ACK、节点重启、迟到
索赔与退款竞争、原TTL保管、结算不可达、协作自刷、试用女巫、整数舍入和真实
提供者到账。测试余额、验签通过或池余额增加都不是生产奖励证明。
本轮仅设计和源码核对，不改金融/AOEM/共识、不执行资产操作、不部署收费。
