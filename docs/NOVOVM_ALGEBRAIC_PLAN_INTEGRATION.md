## 不可误接的相近接口

- AOER 是执行摘要，不是整数行；AOPR 是 u32 primitive 结果，不承接完整 i1024 行。
- AOSQ/AOSR 是持久存储通道，不为导出临时 GPU 结果而写 RocksDB。
- AOTR/AOTS 有二进制编码，但当前相应结果仍包在 JSON hex 字段，不能直接声称无 JSON。
- 旧 opcode 114 的序列生成/固定交易 profile 不是现行真实签名 NOV 业务。
- 通用 u32 scan/Merkle 不等于完整 u128 经济前缀或当前 SHA256 状态树。
- 语义图的 CPU 回调是合法能力，但包裹原 Host 循环不是完整代数编译。

## 实施顺序与每片出口

1. **先接结果边界。** 从现有整数算子取得类型化行，经统一执行入口和上下文所属
   结果通道交接到 exec。版本/能力显式，资源、运行代次、完整长度/形状/位宽/标签
   校验齐全；失败不能读到上次结果。输出采用 DLL 所有权和既有释放规则，不跨 DLL
   裸传 Rust 容器。旧 v7 行为保持；不静默回退。此片不声称完整计划已经完成。
2. **再接可解释的完整计划。** 编译前列出各业务状态与依赖边，复用已有整数 bank、
   条件与常驻图，只为缺失的通用跨阶段资源/效应补适配。费用舍入、资金依赖、
   nonce、失败优先级、国库溢出与受限修复一起表达，不只编译成功路径。
   以一个有界候选委托 AOEM；内部可有多个 CPU/GPU dispatch，不能由 node
   每波读回完整中间值、推进业务状态、再提交下一波。
3. **完整结果回接现有发布。** 对接原候选 effects/receipt/tree，核验原父绑定、
   唯一提交、QC 后发布与重启恢复。不改变共识语义，不把诊断字段加入承诺。
4. **同核验收后替换。** 先逐项经济/错误反例等价，再真实 RPC 四节点冷恢复、
   A/A/B/离线用例和同条件 CPU/整数对照。完整计划未接通期间保留 CPU 默认快路径；
   清理仅针对已有已验收替代的活动路径，保留证据、兼容协议与草稿。

## 固定对照与验收记录

### 本片代码落点与尚未消除的控制往返

首片 AOEM 通用实现已提交并推送为 `8f12c805`：沿 opcode113 新增显式 AOIP0 v8 Run，
复用 v7 已打开的 i1024 常驻资源；结果直接从 `read_limb_results` 编码为
AOIR0001，经上下文/资源/请求代次绑定的单次取回交给 exec。结果读取不执行
任务、不写状态库，旧 v7 格式不变。新 node 正常整数模式要求该能力，不回退
JSON；已有 opt-in v7 profile 是明确的兼容诊断，仍包含 JSON，不能拿它的
路径成本当新二进制路径。CPU 默认不改。实际验收结果另见台账。

### 第二项施工检查点：显式跨行依赖（不签收完整计划）

从 `c48dd7bd` / AOEM `8f12c805` 延续实现：原 NOV 整数程序不重写；node
编译常量与 `Output { row, column }` 绑定，exec 经原 opcode113 交付 AOIP0 v9，
AOEM 校验有界 DAG 并复用原常驻 outcome 算子。最终仍用 AOIR0001 单次取回。
生产整数模式要求显式 dataflow capability，无旧库或 JSON 静默回退。

`business/nov_transfer_batch/dataflow.rs` 的符号表只生成余额/nonce 引用，
不计算后余额。一次 `run_plan` 返回后才重建回执所需的前值；没有边执行边取回、
更新 `ComponentState`、再提交下一波。多分量的独立行仍合批，逻辑行数量不超过
候选/资源容量，依赖层由 AOEM 解释。原方案允许小资源分波消费更大候选；v9
改为候选必须完整装入声明容量，不能截断或丢弃超容量交易。

**这只是完整计划的依赖输入适配，不是第二项完成：**

- AOEM 内部层间仍回读/绑定/上传 limb，不宣称中间值全程 GPU 驻留。
- 各行仍是报价后预测。全局费用容量导致的修复、逐笔结算、状态/回执效应和
  `finish()` 回调尚在；不能用这次单次委托冒充完整候选委托。
- 正常诊断测量实际二进制 `IntegerWire`，不再因开诊断切换到 v7 JSON。
  旧 v7 明细诊断仅保留测试兼容用途，不代表 v9 设备耗时。
- 下一步继续编译费用窗口、暂停/过期、逐笔舍入、三个桶容量与失败前缀，
  将这些条件/效应与依赖连成同一计划，然后移除独立收尾。不能另加 NOV 内核指令。
