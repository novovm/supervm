# 单候选在线确认 V2（实验模式）

本刀把 V2 确认接入现有节点生命周期：本地 prepare 成功后，由本地 poll 调度
确认签名，通过认证 Product Overlay 收发确认票，达到严格超过 2/3 权重后
保存确认凭证并重传。远端 ingress 只验证和暂存，不签名、不写确认凭证。

## 显式开启与范围

在既有 `novovm-native-seal-service/v1` 配置中添加布尔值：

```json
"commit_v2_enabled": true
```

省略或 false 保持 prepare-only。模式和 authority/candidate/signer 一起写入
驱动持久绑定；不能用改配置的方式把已有签名库切换模式。测试部署应使用新的
隔离测试身份/数据集；不要清空旧安全锁，不要让同一身份同时运行多个签名进程。
没有修改现有设备配置、聊天服务、AOEM DLL/ABI/内核或操作员数据库。

当前仅支持同一个已本地执行的候选、固定高度、固定 prepared 轮次，不下载未知
候选，不连续出块。prepare 阶段仍可换主换轮；一旦 prepared，确认阶段不再
换轮或解锁。已为本轮签过 timeout、但没签 commit 的节点仅观察和接收凭证，
不会因迟到 QC 重新获得签名权限。已有确认票可在重启后原样重传。

**活性限制：** 如果不足法定权重的节点能在同一个 prepared 轮次确认，可能停在
prepared；本刀没有声称解决 prepared 跨轮分裂。安全处理是保留证据并停止晋升，
不是删锁或降低票数。跨轮 commit 恢复仍需独立协议设计和验证。

## 线格式与恢复

- 在 `NOVSRW01` 中追加 kind 7（V2 确认票）、8（V2 确认凭证），旧六种编号
  不变。旧接收器会拒绝新增 kind，不存在静默降级；实验网须全部使用支持版。
- 确认票绑定认证发送者；完整法定确认凭证可由任一固定成员转发。消息同时携带
  proposal、prepare QC、必要的 new-view 证据，继续受 192 KiB 帧、嵌套深度、
  集合大小及每来源速率/队列限制。汇票依据 V2 target，不按 QC hash 分组。
- 早于本地 prepare 的确认消息被忽略，但不进入已处理去重缓存；重传可重试。
- 确认票先持久化后发送。每次 poll 检查持久证据；凭证及本地投票另有恢复标记。
  凭证已落盘、标记未写入时可恢复；已标记凭证丢失/改变或本地投票记录丢失
  则报错停机，不重建假成功。本地签名重传前重新完整验证，确认完成后只重传
  已验证凭证。收到的远端票可从重传重新收集，未增加无界远端票持久日志。

## 对外状态与未完成项

`commit_confirmed=true` 表示本节点已保存并验证 V2 法定确认凭证；
`commit_certificate_hash` 标识实际保存的证据，不是全网唯一目标 hash。
该状态**不等于最终块**，`proof_sealed/chain_canonical/safe/finalized` 仍为 false。
停机状态压低确认成功标志，不继续宣称成功。

测试覆盖独立签名者/数据库的确认、乱序重复、2/4 拒绝、3/4 成证、prepare
换主后的非零轮确认、迟到 QC 的超时隔离、重启和凭证丢失；另以本机真实 WSS
四节点服务验证自动收发与持久恢复。候选仍为合成执行事实，不是 AOEM 实机验收。
实体局域网、公网、物理断电与长期运行未在本刀执行。

下一步仍需解决跨轮 commit 活性、最终祖先/fork choice 与 AOEM/ledger
跨库可恢复晋升，不能依据 `commit_confirmed` 直接修改最终性字段。

后续已补[跨轮完整确认凭证追赶](NOVOVM_NATIVE_SEAL_COMMIT_CATCHUP_V2.md)：
观察并归档其他轮次已有的完整凭证，不改变自己的轮次或签名锁。新增
`commit_round` 和 `commit_observed` 区分凭证轮次/来源；零散票跨轮活性仍未解决。
观察路径也可从其他轮次同一目标的足额认证确认票组装凭证；不同目标/轮次不混票。
