# 原生封印超时观察与持久化签名保护 V1

本次为轮次恢复的基础切片，不是已上线的换主协议。新增 native_block_seal::timeout，复用现有 seal RocksDB、同进程共享写锁、不可变验证者集合与候选账本身份绑定。

## 已实现

- 超时观察签名绑定独立协议域、chain ID、genesis hash、协议配置承诺、epoch、validator-set hash、高度、轮次及签名者。
- 本机调度器调用 sign_local_timeout；检查本地账本身份、集合成员、激活高度及本地 head+1 的前瞻上限。不接公开 RPC，不把远端请求当作本机超时。
- 签名对象与单调签名水位使用同一同步 RocksDB batch 落盘并读回后才返回。相同位置重试返回同一份签名；重启保留；缺失对象或冲突存储拒绝签名。签名对象本身是按 slot 取回的重发记录，尚无网络自动消费队列。
- 超时后拒绝签该高度/轮次及更早位置的 proposal/vote；检查与原有签名路径共享写锁，因此超时与普通签名并发时顺序明确。旧候选 height lock 不解除。
- 超时证书逐个严格验签，拒绝重复签名者、混合上下文、错误期望网络域、空证书和过多签名；重新计算实际权重，要求严格大于总权重 2/3。没有信任外部声明的签名权重。

## 边界与后续

超时观察只表示签名者停止对该位置继续签名，不证明真实经过了多长时间，也不证明某个候选安全。证书不是 proof seal、提交证书或解锁依据。已新增显式启用的本地持久化轮次跟踪和单调计时器；尚未携带经验证的最高 QC、实现安全提案选择、完整 pacemaker、自动传播或 epoch 切换。

因此本次保留 Overlay 的第 0 轮准入限制，也不设置 chain_canonical / proof_sealed / safe / finalized。继续实现时必须先明确最高 QC 与候选锁的安全规则，再接超时证书驱动的换主；禁止仅根据这份超时权重证书释放旧锁。

## 验证范围

新增检查涵盖 RocksDB 重启、超时后的签名拒绝、相同 slot 重发、回退轮次拒绝、未来高度限制、只读数据库、伪造签名、重复签名、不足 3/4、错误 genesis、缺失持久化对象、非成员、加权法定人数与多句柄并发幂等。

验证结果：cargo test -p novovm-node --lib native_block_seal -- --test-threads=2，21 项通过，0 失败；包括超时观察、轮次跟踪和计时器测试与现有封印/隔离接收回归。没有生产部署或多机器验收，不改 AOEM。


## 本地轮次跟踪与计时器（第二批）

- start_round_tracking 显式初始化本地轮次；再次调用读取原状态，重启不会重置到第 0 轮。应在该高度开始签名前初始化；未启用跟踪的既有调用路径保持兼容。
- advance_round_tracking 只接受当前轮次的有效超时法定人数证书，同步持久化下一轮及前一轮证书。跳轮拒绝，已验证的旧证书幂等返回当前状态；加载时重新检查网络域及证书。
- 启用后，proposal、vote 与 timeout 签名必须匹配持久化的当前轮次，即使本机未签过上一轮 timeout 也不能继续签旧轮。保留既有候选高度锁；轮次推进不授权切换到冲突候选。
- NovNativeSealRoundTimerV1 使用进程内单调时钟；到期才返回已持久化的本机超时签名，重复轮询用于重发。轮次已推进的旧计时器不再产生签名；重启后等待完整的新间隔，不依赖系统墙钟。
- 计时器需要调用方轮询，尚未接入节点主循环或网络广播。它不是已经运行的自动换主服务。最高 QC / new-view 的安全提案选择仍待完成，Overlay 仍只接收第 0 轮。

新增两项测试覆盖：初始化与重启恢复、顺序法定人数推进、拒绝不足权重和跳轮、旧/未来轮签名拒绝、只读写入拒绝，以及计时器到期边界、重发幂等、旧计时器失效和下一轮重新计时。测试使用本地账本夹具，不代表真实 AOEM 多机共识验收。
