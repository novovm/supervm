# 原生封印超时观察与持久化签名保护 V1

本次为轮次恢复的基础切片，不是已上线的换主协议。新增 native_block_seal::timeout，复用现有 seal RocksDB、同进程共享写锁、不可变验证者集合与候选账本身份绑定。

## 已实现

- 超时观察签名绑定独立协议域、chain ID、genesis hash、协议配置承诺、epoch、validator-set hash、高度、轮次及签名者。
- 本机调度器调用 sign_local_timeout；检查本地账本身份、集合成员、激活高度及本地 head+1 的前瞻上限。不接公开 RPC，不把远端请求当作本机超时。
- 签名对象与单调签名水位使用同一同步 RocksDB batch 落盘并读回后才返回。相同位置重试返回同一份签名；重启保留；缺失对象或冲突存储拒绝签名。签名对象本身是按 slot 取回的重发记录，尚无网络自动消费队列。
- 超时后拒绝签该高度/轮次及更早位置的 proposal/vote；检查与原有签名路径共享写锁，因此超时与普通签名并发时顺序明确。旧候选 height lock 不解除。
- 超时证书逐个严格验签，拒绝重复签名者、混合上下文、错误期望网络域、空证书和过多签名；重新计算实际权重，要求严格大于总权重 2/3。没有信任外部声明的签名权重。

## 边界与后续

超时观察只表示签名者停止对该位置继续签名，不证明真实经过了多长时间，也不证明某个候选安全。证书不是 proof seal、提交证书或解锁依据。尚未携带经验证的最高 QC、实现安全提案选择、timer/pacemaker、持久化轮次激活、自动传播或 epoch 切换。

因此本次保留 Overlay 的第 0 轮准入限制，也不设置 chain_canonical / proof_sealed / safe / finalized。继续实现时必须先明确最高 QC 与候选锁的安全规则，再接超时证书驱动的换主；禁止仅根据这份超时权重证书释放旧锁。

## 验证范围

新增检查涵盖 RocksDB 重启、超时后的签名拒绝、相同 slot 重发、回退轮次拒绝、未来高度限制、只读数据库、伪造签名、重复签名、不足 3/4、错误 genesis、缺失持久化对象、非成员、加权法定人数与多句柄并发幂等。

验证结果：cargo test -p novovm-node --lib native_block_seal -- --test-threads=2，19 项通过，0 失败；包括新增 4 项测试与现有封印/隔离接收回归。没有生产部署或多机器验收，不改 AOEM。
