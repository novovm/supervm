### 授权页写集收敛（v4之后）

源码确认：常规grant占一个数据页，但固定512字节记录每次更新都会输出
`Put长度头/Put数据页/Delete本已缺失的尾页`。1024独立授权就产生1024次此Delete，
打断原树planner的连续Put批量构造；16账户同块只需对去重后的16份授权做此工作。
这不是ML-DSA数学开销，也不应靠放松尾页规范性来解决。

候选沿原codec比较同父根已完整校验/解码的旧grant与新grant，只提交实际不同页。
旧记录使用捕获时的原intent编码，避免管理换epoch时错误套用新epoch；None及新开户仍全量，
真正旧尾页缩短继续Delete。原读集、授权、守恒、nonce、费用、原树格式及原执行/journal不变。

### v6：收敛重复持有，修复缺口源的原队列交接

本候选仍沿原APFL输入/交易池、CandidatePipeline、NovoRUDP及journal；没有另建账户、
UDP、共识或执行入口，没有扩大原64MiB池或两槽source队列。修改范围：

- `novovm-exec::uca_spend`将已经通过验签的owned对象消费为私有紧凑签名事实；
  原APFL owner只保留一份公钥和签名字节。事实绑定完整规范intent、ML-DSA-65参数、
  pure用途framing、公钥和签名；候选按原owner和完整行匹配重新挂接，不重复ML-DSA验签，
  不继承过期授权结论。外部不能构造/反序列化此事实。
- 原authority被池背压挡住时，将剩余checked行及原字节permit回交**同一个**source队列。
  只释放占用的阶段角色，所有字节继续计费；父状态/池未变化则不重新捕获，变化时仍重验权限。

- 未来nonce不能抢走现有池中一行真实桥接交易所需的槽位/字节；仅实际压力时检查连续前缀。
  大APFL owner妨碍桥接时，沿原APFL单行投影保留同一完整签名事实，不重新验签。
- 原不可变候选packet一次建立实际回执nonce索引；后继反复检查共享同一Arc，避免每次等待

### 综合签收边界及剩余限制

本检查点一次合并v6活性、v7状态/APFL复用、v8选批等待和准入去往返；保留各冻结二进制、
源码差异、未通过的旧行为反例与完整公开报告。没有创建新网络、账本、权限系统或执行器。

- 已有确定性证据：池背压不再永久挡住迟到nonce桥接；签名事实/原APFL只读正文复用不扩大
  授权；费用尾页不再产生无效Delete；同根键物化减少重复树遍历；同条件重复选批减少。
- 正确性：最终候选557项原生默认回归、对应显式签名/授权/归档/后继反例、四真实原进程恢复、
  运行中开户及再消费，以及每轮负载的费用/余额/权限/nonce/原库冷恢复通过。默认忽略项、
  历史默认并发/WSS失败、Linux、多机和完整候选CI均不因此算通过。
- 性能：1024账户当前约1.9K，未达到3.5K或历史12K；相邻同字节CPU小幅正向、GPU负向，
  不宣布稳定提速。P95/P99始终为首发尝试至四方回执查询观察，不偷换成内部最终确认。
- 原网络仍是已存在的 `transport/native_ingress` → `novorudp/datagram` →
  `novorudp/carrier.rs` UDP实现；Windows实际逐包 `send_to`/`recv_from`，未新增UDP旁路。
  最新入口NativeIo累计约4.88秒/16K诊断仍未下降；其逐包加解密、系统收发和正文流量是
  尚未解决的具体成本。旧测量中细分采样可参考原IO报告，但不能把旧采样比例套成v8实测，
  也不能将整个NativeIo墙钟说成网卡带宽极限或CPU利用率。
- 16与1024付款账户同时改变公钥/状态分布、APFL字节数和依赖分布。当前证据不足以把所有
  TPS差额归给任一项，更不能以“许多用户天然慢”签收。保留原4进程/1024账户主验收。

本轮只在批准的开发分支保存候选；main、正式随包库、部署、签名/费用/nonce/法定票数及
生产超时不变。没有清理既有数据库或journal。性能恢复任务继续记未完成，不以局部工作减少
或测试数量代替产品性能达标。
