[原失败报告](payers65536-v1-failed.raw.zip)与日志保留。

此修正只改变初始化批次，不建立账户总数限制；v1数据不替修正后的候选背书。

最后一个请求`sent=false`，未发送任何交易，TPS为null，不登记为0 TPS。
[准备超时原报告](payers65536-v2-readiness-failed.raw.zip)。

源代码核对确认测试夹具在节点初始化前就创建客户端；初始握手30秒过期后，
原Status重试仅重发查询、不会重建握手。node0的tick启动日志约在173秒后出现，
因此此过期客户端不能证明节点后来是否就绪，也不能用于转账性能归因。
其他节点的空stdout不足以单独证明死锁；本轮不以猜测替代后续复验。

同时发现两处可直接消除的重复工作：安装器已完整批量校验和回读初始内容，外层仍逐个
重读约183.5万初始节点；UCA启动先构建普通分配树，随后构建完整初态并丢弃前者。
候选修正保留所有原pin、签名、冲突拒绝和批量回读，只移除这两次重复准备。
准备客户端仅在类型化查询超时、从未认证且握手已过期时使用原构造器重建；
原单次握手/查询期限、总准备期限及四方回执计时终点不变。此修正尚待独立制品复验。
