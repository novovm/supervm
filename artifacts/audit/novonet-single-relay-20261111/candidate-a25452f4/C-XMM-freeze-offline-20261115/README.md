# 冻结断点取证，继续Clone离线数据流核对

## 当前处置

本轮按用户要求冻结四检查点及入口/返回轮换方案。两个本机诊断目录均新增FROZEN标记，Launch-Once及Invoke-Elevated在进入提权/任务流程前检查该标记，防止误用旧入口。四份入口语法核对通过。历史三组数据及失败现场保留，诊断文件继续独立于产品。

本轮只读进程清单未发现novovm-node、novovm-base-a254、novovm-xmm4-a254或CDB进程。原novovm-node.exe的WER规则仍为DumpType=2、DumpCount=2，并指向此前验收的LocalService专属目录。本轮只读规则，没有重新测试目录写入或启动节点。原节点当前停止，因此没有正在运行的自然故障等待任务。遵循用户本轮不重启、不访问原库和身份的限制，原现场继续保持。

readiness-public.json保留实际UTC、进程查询结果和WER值。原始运行路径需要与节点实际运行状态区分，保留WER规则本身不会让已停止的进程产生自然异常。

## Clone的XMM7来源需要补充一条合法临时重定义

原PID3848完整转储、匹配a254 EXE的同一机器码证明以下数据流。指令字节及地址在clone-flow-public.json中逐点保留。

| RVA | 原指令及意义 |
|---|---|
| 0x15a581b / 0x15a5822 | 把调用者XMM7/XMM6保存到RBP+0x210/+0x200 |
| 0x15a5887 | movups xmm6,[rdi+0x2a0] |
| 0x15a58d1 | movups xmm7,[rdi+0x2b0] |
| 0x15a5a53 | movups xmm14,[rdi+0x320] |
| 0x15a5c29 | 把当前XMM7保存到局部RBP+0x10 |
| 0x15a5c7d | 某分支movaps xmm7,xmm14，合法临时重定义 |
| 0x15a5ce3 / 0x15a5d3b | 对应路径将临时XMM7搬回XMM14 |
| 0x15a607e | 将XMM6搬到目标记录+0x2a0 |
| 0x15a6085 / 0x15a6089 | 经XMM0将RBP+0x10搬到目标记录+0x2b0 |
| 0x15a61c0 / 0x15a61c7 | 从原保存区恢复调用者XMM6/XMM7 |

因此source+0x2b0的载入并不是函数中最后一次写XMM7。返回前某分支中的临时XMM7还可能来自先前的XMM14；它与原+0x2b0局部副本分别保存。RBP+0x10局部副本和RBP+0x210调用者保存槽相隔0x200，不存在基于正确帧基址的静态地址重叠。

这些是合法的函数内寄存器使用。它们没有证明历史返回恢复失败，也没有把0x15a5c7d认定为破坏指令。所需证据仍是实际执行的分支、当时RBP和保存槽原值。

本轮将同次DMP最终存活的255条原记录，在+0x2a0、+0x2b0、+0x310和+0x320四处的16字节值分别与坏XMM6、坏XMM7比较，均没有匹配。此前只比对原+0x2a0/+0x2b0的32字节，本次补充临时XMM14来源的范围。最终数据不等于历史输入，不能据此排除已释放/复用记录或其他内存破坏。

精确PDB的TPI类型流已读取，共5612个记录，没有找到NativeTransferEvidenceV1具名类型记录。当前仍不能把这几个偏移可靠标成某个Rust字段名；Rust源码声明顺序没有被当作实际布局。原PDB和原转储保持原件。

## 动态目标和ABI证据范围

Clone自身有六处原直接call，归为三个目标，包括分配错误路径、无分配shim、Rust分配器入口。该函数已解码控制流内没有未解析的寄存器/vtable call，静态目标不再向整个项目扩展。

原分配入口继续跳到既有全局分配器；其他已审查路径存在VCRUNTIME140 memcpy导入，IAT在同次DMP可解析。具体系统DLL内部执行分支、历史返回和恢复槽值仍无法从终态恢复，不能将静态IAT地址充当实际逐次调用记录。Clone有异常处理元数据，但元数据存在不能证明本次执行过异常展开。

本轮没有新增证据将Clone的实际返回连接到Windows/SysV ABI违规，也没有建立它与PID34452的RBP偏移共同根因。首次破坏位置仍未找到，生产代码没有猜测性修补。

## Intel PT的当前可用性与历史资格

本机只读CPUID查询中leaf7.EBX=0x239c27a9，bit25为1；leaf14有有效能力值。本机进程所见CPU宣告Intel PT支持。当前CPU型号为i9-14900HX，32逻辑处理器，Windows 26300.9974；WPR -status退出0并显示未录制。CPUID的PT枚举位置见Intel SDM Volume2A Table3-8。[Intel官方手册](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf)

已有资格实验早已实际生成并解码PT，也取得目标线程和模块关联。这轮复用其结果，没有重复同配置或普通样例。此前缺口仍然有效。

- 异常尾部三个片段只有同步/控制包，原字节审计未找到隐藏TIP/TNT。
- 最后一次CPU9切出事件存在，对应PT指令片段缺失。不能再写成CSwitch缺失。
- ETW options、writePosition仍没有被证明为硬件TraceEn和ToPA寄存器值。
- 现有环境未验证与Windows跟踪所有者协调的逐CPU状态读取通道。
- 既有约3%短时资格开销无法证明原NOVONET自然故障窗口的完整覆盖或长期时序影响合格。

因此PT具有基础可采集/可解码能力，原故障尾部控制流保留和低干扰资格仍未通过。它也没有提供本次历史XMM6/XMM7数值变化。PT-evidence-public.json固定本轮复核的既有报告哈希，相关原始ETL和转储留在本机。
