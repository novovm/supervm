## 判定目标：首次违反当前活动帧的保存约束，不是首次写 RBP

合法子函数可以暂用 RBP。比如一个子函数建立自己的帧后，RBP 不等于父函数的
`RSP+0x100` 是正常行为。父帧不变量只在父函数相应机器码区间适用；子调用返回时才比较
该调用前后非易失寄存器的保存义务。不能把所有 `mov/lea/pop rbp` 都当异常。

对原故障函数，取证关联键至少需要：

```text
process_creation + thread_creation + activation_sequence
entry_rsp + return_address + module_build_id
call_sequence + call_depth + pre_call_rsp + expected_return_address
```

不能用一个全局 `$t0` 缓存 RBP；多线程或递归进入会覆盖它。只看线程 ID 也不能区分
同一线程上的嵌套调用和下一次复用的栈地址。

具体事件及判定：

| 位置 | 必须保存 | 可作出的结论 |
|---|---|---|
| 函数入口 | TID/创建标识、入口 RIP/RSP/RBP、返回地址 | 建立 activation，尚未套用建立帧后的关系 |
| 序言完成 | 实际 RSP/RBP、保存调用者 RBP 的槽地址及值、代码哈希 | 验证本帧 RBP=RSP+0x100；此处需与实时字节相符 |
| 每个被覆盖的 CALL 前 | 调用序号、目标地址、父帧 RBP/RSP、将返回的位置 | 建立该子调用的比较基线，不假定子函数不使用 RBP |
| 对应 CALL 返回后 | 同一 activation/call、RBP/RSP、RIP、保存槽 | 若前后不一致，可定位到该次调用区间；仍未定位区间内首次写入 |
| 候选恢复指令前后 | RIP、机器码、源操作数地址/值、RBP 旧值/新值、活动帧 | 足够时才指向具体恢复指令；正常恢复不算错误 |
| 异常/非局部恢复 | 恢复前上下文、目标上下文、实际恢复后活动帧 | 区分合法离开父帧与错误恢复；取消已离开的 activation |

对 `RtlRestoreContext`/`NtContinue`、异常展开和非局部跳转，若不能可靠关联恢复前后，
必须标记 **context_gap** 并停止因果归属，不能把迟到返回或复用的栈位置连接成一条轨迹。
该清单是覆盖要求，不宣称只监视两个 API 就涵盖所有可能上下文变更。

每段证据还必须区分：实际执行记录、根据快照计算的值、静态候选指令。

## 现有工具能做什么、不能做什么

| 手段 | 能力 | 对本次目标的限制 |
|---|---|---|
| 硬件写断点 | 观察选定内存位置的写入 | 不能直接监视寄存器 RBP；尚未证明应选哪个活动保存槽，不能盲监旧地址 fee000 |
| 候选指令执行断点 | 在特定指令处取寄存器/内存 | 只覆盖已选位置，不能自动补出其前面全部历史；数量有限，不能假称覆盖所有写路径 |
| 条件断点 | 用调试器表达式筛选需要呈现的命中 | `/w` 不是已验证的零开销记录器；减少输出不等于保持原线程时序 |
| WinDbg `t` | 对运行中的目标单步并显示寄存器 | 不是 DMP 回放；线程限定时会冻结其他线程，不能拿单步正常结果证明原并发条件安全 |
| WER Full Dump | 完整终态内存与上下文 | 已合格，但不能提供最后一次正确 RBP 到首次错误 RBP 的全部指令历史 |

依据微软官方文档：[ba](https://learn.microsoft.com/en-us/windows-hardware/drivers/debuggercmds/ba--break-on-access-)、
[conditional breakpoints](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/setting-a-conditional-breakpoint)、
[t / Trace](https://learn.microsoft.com/en-us/windows-hardware/drivers/debuggercmds/t--trace-)。
开销是否可接受须由实际测量决定；本轮未运行测量，不提出未经验证的低干扰承诺。
