# PID44948与PID43712独立离线数据流

## 结论和执行范围

两份Full Dump按原SHA-256重新核验。本轮只读取转储、原始EXE和已有公开源码。
没有运行节点、样例或采集实验，没有修改生产代码、诊断二进制或启动配置。
PID44948首次异常XMM定义仍未定位。PID43712首次非法源指针定义仍未定位。
现有数据未证明共同根因，也未证明诊断副本异常必然由诊断改写引入。
本轮没有具备证据基础的修复补丁，原库、身份和失败现场保留，双中继继续暂停。

### 指令级传播和证据缺口

以下NOVOVM地址均为相对该次EXE模块基址的RVA。VCRUNTIME地址相对其自身模块。

| 位置 | 机器码作用 | 已取得与尚缺证据 |
|---|---|---|
| LowerHex 0x1e50331～0x1e50354 | 形成栈上数字串指针、长度并写第五/六参数，调用pad_integral | 活动参数槽和两字节缓冲区当前有效，历史入口值未记录 |
| pad_integral 0x1e52f48/0x1e52f4c | 第五参数存入本帧RBP-0x10 | 原代码已核对，该已返回帧的历史局部值缺失 |
| pad_integral 0x1e52fde/0x1e52fe2/0x1e52ff5 | 取局部源指针到RDX、长度到R8，恢复帧后尾跳writer | 尾跳前RDX没有历史采样 |
| String 0x1e4ccaa/0x1e4ccb3/0x1e4ccb8 | reserve路径将源RDX暂存R14，调用reserve后恢复RDX | 当前R14与坏RDX相等，缺少实际save前及reserve前后上下文 |
| String 0x1e4cc84～0x1e4cc8e | 目标buf+len，传长度并调用memcpy | 当前目标与描述符吻合，源指针已非法 |
| VCRUNTIME 0x13010→0x11200→0x11268 | memcpy入口跳转，长度2查分派表并读取[RDX] | 分派表长度2目标为0x11268，前缀没有RDX写入或嵌套调用 |

因此，VCRUNTIME两字节分派前缀没有形成这个非法RDX。
该结论来自实际入口、分派表和指令语义核验，不依赖将错误RVA上的无关指令当成writer。
它仍不能确定RDX在pad局部重载、尾调用、String入口或reserve保存恢复区间的哪一刻首次变坏。
当前R14与RDX相等不能单独证明reserve正确保存了R14，也不能证明调用前源值已经错误。

### 为什么当前栈槽不能补成历史

按pad序言计算，其旧局部源槽为0xf3bd3ee6f0，当前内容为0xf3bd3ee720。
String调用reserve后，reserve入口0x24334a0的push rbp会合法复用该地址，写入String.RBP=0xf3bd3ee720。
当前内容与这一合法栈复用计算吻合，但仍不把它当成运行历史的独立采样。
不能据此声称pad当时把0xf3bd3ee720作为源，也不能据此宣布发生栈覆盖。
必须保留未知的历史源值。两份DMP均缺少足以定位首次变化的执行记录。
