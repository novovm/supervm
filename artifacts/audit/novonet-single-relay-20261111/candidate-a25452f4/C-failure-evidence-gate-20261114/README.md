## 3. 六项证据必须绑定一次失败

| 项目 | 当前边界 | 新现场最低要求 |
|---|---|---|
| Formatter/局部 String | 有最终快照值 | 在已证明对象存活的调用边界读取，不能假定最终值就是调用前值 |
| writer 接收对象及文本参数 | 有最终异常值 | 同线程、同调用关联的 writer 入口和复制前实际值 |
| 调用前后寄存器/栈 | 缺失历史 | 覆盖最后一个已知正确值至第一个错误值，标识丢失/截断记录 |
| 对应代码页 | 部分代码仅有磁盘镜像 | 同次失败捕获相关实际执行代码及模块身份，区分磁盘回填 |
| 目标堆页 | PID37796 record 不完整 | 同次失败包含目标 record、相关对象及能核验的所有权状态 |
| 线程/调用上下文 | 有 WER 时刻栈 | 同次运行的线程、调用序号和必要调度/生命周期证据；等待栈不代替历史 |

若要做真实负载的隔离重放，还缺该次输入及事件顺序、相应起始状态、超时/随机性
和对端协议上下文。仅按累计计数生成新包不叫重放。协议输入重放即使可建立，也
不保证复现原线程调度或原堆布局；若找不到失败，必须保留这一限制。
本轮不复制原库/身份到隔离环境，也不因缺少这些材料就伪造“原始业务负载”。
