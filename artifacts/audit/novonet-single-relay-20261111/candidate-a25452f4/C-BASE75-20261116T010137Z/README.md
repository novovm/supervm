## 本次自然故障的直接证据

节点2 / PID39152在本轮启动后约648秒产生异常转储，控制器651.378秒完成停止。原始异常TID676，0xC0000409、子码7。其余三节点0xE0000001是控制器收尾终止；owner退出0只表示采集脚本完成。

完整转储210,746,528字节，FullMemory标志、19线程上下文、421个内存范围和稳定SHA-256均核验。原始转储留本机。

调用链为status → Core::insert_full → reserve_rehash → fallible_with_capacity → handle_alloc_error → rust_oom → int29h。首次插入键reads_started，entries长度和容量均为0。

| RawTable字段 | 本次实际值 | 合法模板 |
|---|---|---|
| ctrl | 0x7ff77b3b5400 | 0x7ff77b3b5400 |
| bucket_mask | 0 | 0 |
| growth_left | 0 | 0 |
| items | 0x18e3c1f7510 | 0 |

前三字段等于合法空表模板，只有items异常。32字节逐字节等于异常上下文XMM6/XMM7及当前insert_full保存槽；XMM6合法，XMM7低64位合法、高64位异常。原始字节及地址见allocation-comparison-public.json。

按表字段计算请求19,791,209,299,984字节（18TiB+16B），与stderr及异常RBX一致；历史PID44948为36TiB+16B，不能写成分配大小完全相同。

status直接写入RawTable的RVA0x77823e/0x778245、insert_full本体及status调用点均与原EXE字节一致；保存的调用者RBP和返回地址与本次帧关系匹配。当前帧没有发现历史0x2A0偏移，不据此排除历史故障。

本次在新库、新测试身份、环回网络负载下复现了相同业务路径和损坏元数据导致巨额申请的故障形态。原生产库或生产身份并非复现这一形态的必要条件；这不证明所有历史故障有共同根因。

最后完整状态报告在故障前约8秒产生，并非故障瞬间对象快照。该节点保留2048条delivery记录、256条transport记录，累计淘汰699、过期647；交易执行及实际归档读取均为0。全组516份状态报告，WHEA前后成功查询、新增0条；没有WHEA不证明硬件正常。

仍缺少模板载入到初始化之间的历史寄存器变化。已证明异常使用与传播，未证明首次破坏指令、ABI违规或与诊断副本PID43712共同根因。后续重点是本次XMM7高64位/items的来源；本轮不追加运行、不提交猜测性修复。
