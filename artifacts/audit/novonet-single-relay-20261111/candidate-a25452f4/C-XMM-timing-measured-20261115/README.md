# 原 a254 的完整status计时三组隔离实测

## 本轮执行结果

用户重新确认Windows UAC后，本轮于北京时间2026-11-15 17:02至17:12执行三组短时隔离测量。三组均由LocalService运行原a254＋AOEM966，使用新隔离数据库和各组独立测试身份。所有12个节点进程均由180秒原生时限结束，退出码0；新测试任务和专属WER规则已清理，WHEA前后无新增记录。原库、原身份及旧失败现场保留。

完整status耗时三组中位数分别为14.4481ms、26.8388ms、123.52645ms。入口/返回与四点复用的测量组明显改变完整查询耗时，本轮判定不具备长期故障取证资格。未进行66分钟或更长运行，双中继暂停，原始根因仍未定位。

## 原二进制和计时来源

EXE SHA256为1758e4a79dd34d1688d8f7bf4b60f46ed9ced518186f42fdb16baf04c0d0c46d，AOEM966为5743f5875131330f8c8fec58cdc2a85aa39dc6e9689358609a5f0a09a01c0d52。未重建二进制。

三组统一启用原a254自带NOVOVM_PROFILE_STAGES=1。原主tick通过observe_tick(TickStage::Status, || product.status())包住查询，记录tick_status的calls和inclusive wall_ns。相邻快照calls差为1时，wall_ns差提供上一条已完成status的完整inclusive wall耗时。每组得到30个单调用样本，没有计数跳跃。

profile::snapshot位于当前查询内部，计数天然滞后一条。计数快照为非原子，本次隔离没有外部RPC监听，单调用差分仍限定在计数增量恰为1的样本。该计时包含调试暂停；它与报告文件间隔分别记录。

原生profiling在上轮2b5a5b5c和历史PID3848中关闭，开启它会增加诊断工作并改变profile快照构造路径。本轮用于验证计时和短时干扰，其数据不能直接接续上轮作为同一构建配置的长跑。

## 四槽复用与同次调用关联

为测量入口到正常返回，本轮在四个硬件槽中时分复用六个逻辑位置。

| 逻辑位置 | 原RVA | 作用 |
|---|---|---|
| ENTRY | 0x772120 | 原函数序言前 |
| P0 | 0x7721fb | 合法模板载入后 |
| P1 | 0x777bad | signature_work发布后 |
| P2 | 0x777c36 | network_probe_observation返回后 |
| P3 | 0x77823e | archive_work写表前 |
| EXIT | 0x779ec5 | 原正常RET边界 |

槽0在ENTRY/P0之间切换，槽3在P3/EXIT之间切换。入口到P0期间其他线程的新入口可能未被观察，重叠活动调用会停止并保留记录；该方案不能承诺全部线程和全部调用覆盖。四个原父帧检查点保持原地址，实际同时启用的硬件地址不超过四个。新增入口/返回停顿和槽重配置使本轮与上轮纯四点方案有明确差异。

实际status线程8076取得34组完整ENTRY→P0→P1→P2→P3→EXIT，合计204条事件。全部136个P0-P3原始32字节均等于该进程的合法模板，34组EXIT向量均等于同次ENTRY原值。每条事件核对调试器视角的DR0-DR3/DR7及原RIP。原始CONTEXT留在本机受保护目录，公开的ENTRY/EXIT向量值已省略，保留局部检查结果。已观察入口的调用没有缺点或未完成组，204个继续命令都有确认记录。

当前寄存器值在ENTRY/EXIT可以合法不同于模板，模板检查仅适用于P0-P3。Windows ABI保存恢复检查采用同次入口与出口值比较。34次正常调用不能排除历史Clone路径恢复异常。

## 新的响应和暂停测量

控制器响应时间现在在字段计算完成、继续命令写入之后持久化。公开timing-events-public.jsonl和resume-ack-public.jsonl逐条关联事件编号，修复了此前字段未写出的缺陷。

| 已测指标 | 样本数 | P50 | P95 | 最大值 |
|---|---|---|---|---|
| 控制器通知可见至继续命令写完 | 204 | 1.400ms | 3.241ms | 11.443ms |
| 已知目标暂停区间的保守下界 | 204 | 1.384ms | 3.231ms | 11.420ms |
| 命令写完至调试器echo通知可见 | 204 | 16.291ms | 23.930ms | 32.636ms |
| ENTRY通知至RET边界通知 | 34 | 108.101ms | 145.599ms | 162.999ms |

ENTRY/RET通知跨度覆盖函数体和尾声，并含调试器及控制器延迟；RET指令当时尚未执行。原生observe_tick的完整inclusive wall还覆盖边界外的入口调试分发、返回停顿、RET及调用者计时收尾，故两种时间口径各自保留，没有逐条硬拼成相同数值。

CDB日志可见时刻属于控制器观测；echo在g之前执行，echo可见也不等于目标线程实际恢复。当前没有内核调试事件的精确stop/resume时间戳。已知暂停下界不能当作全部暂停时间，不能从完整墙钟中扣除后宣称无调试器耗时。具体开始、处理、发送和确认的单调时间戳均在公开事件中。

## 退出与收尾的原始口径

每组四个节点自身的内核进程句柄退出码均为0。两组调试器最终退出码也为0，但控制器都记录了controller_terminated_debugger收尾请求，发生在节点已结束之后。该动作及退出码同时保留，不能仅凭退出码0把调试器收尾写成完全自主退出。没有以控制器终止制造目标自然崩溃，也没有本轮自然异常记录。

新任务Ready、LastTaskResult=0，随后删除任务。只为新测试EXE设置的WER规则已删除，历史规则保留。原库、身份和历史失败记录未打开或修改。

## 负载和资格决定

三组实际网络对象最大保留数均256。基线最后expired84/evicted146、仅附加expired86/evicted173、计时组expired93/evicted174，均发生持续周转。各组末次写计数约2561、2562、2611，实际计数详见measurement-public.json。
