## 已核对的原生完整调用计时

原a254源码在主tick中用observe_tick(TickStage::Status, || product.status())包住整次查询。原profile::mark/work使用Instant并累计tick_status的calls、wall_ns、max_wall_ns，该能力由原NOVOVM_PROFILE_STAGES开关启用。源码取自a25452f4，三份相关文件哈希已记录。

因此原二进制本身已有可选的完整查询计时。上轮阶段配置关闭了它，不能从上轮记录补造逐查询耗时。新的三组隔离测量将统一启用NOVOVM_PROFILE_STAGES=1，先依据实际输出确认计数器生效。相邻快照calls增量恰为1且wall_ns单调时，可取差值得到上一已完成查询的inclusive wall时间；计数增量大于1时只保存聚合和缺失标记。查询内部生成的快照早于当前查询结束，天然滞后一条；该事实必须保留。

原profile快照文档注明非原子，单查询差分还要求同一计数器没有额外生产者。隔离配置没有外部RPC监听，运行时仍须核对观测线程和计数增量。关闭调试器、仅附加以及四点组都使用同一原生计时配置；这一配置相对历史故障的profile关闭状态有差异，不能把测量组直接称作历史原样复现。原生计时的inclusive wall也包含调试器暂停时间。

## 控制器时间字段已修正，运行资格仍待验证

上轮事件在controller_response_ns赋值前写出文件，导致响应字段丢失。新接线先完成继续命令写入并计算时间，再持久化事件。每条事件分别记录日志可见时间、开始处理时间、发送前时间、继续命令写入完成时间和后续调试器echo确认。语法编译及字段写入顺序已核对，实际回调尚未运行。

完整status入口RVA0x772120、正常RET边界RVA0x779ec5与原同次完整转储的代码字节一致。原函数已解码正常出口只有这一处RET。入口/返回观察需要与四个原检查点复用DR0-DR3，逻辑观察位置增加为六处，最多四个硬件槽同时启用。新增的两次停顿和槽重配置开销也需计入干扰，不能把这版等同于上轮四点组。

入口/RET观察按线程、入口RSP、返回地址及栈边界关联，重叠活动调用或缺点时标记失败。动态槽复用在入口至模板检查点之间留有其他线程入口未被监控的区间，不能据此承诺全线程完整历史。RET点记录时函数体及尾声已完成，RET指令本身尚未执行。

外部控制器能给出可复核的观察时间、处理时间和一段目标已停住的保守下界。CDB日志的可见时间不等于内核调试事件产生时间，echo也不等于线程真正恢复执行的时间。当前接线没有精确内核stop/resume时间戳，不能把该下界写成完整调试暂停时间，不能从墙钟中扣掉它后宣称得到了无调试器查询耗时。

资源采样增加目标、CDB和控制器CPU/内存，以及目标线程CPU计数、周期和上下文切换计数。它们属于资源和线程执行量，仍缺完整的CSwitch/调度事件时间线。本轮没有为弥补这一缺口增加WPR/PT或新内核采集器。
