# C：同次调用采集器已实现并实跑，原始首次错位仍未找到

2026-11-15（北京时间）。接续 `f7d2bd23`，C 独立执行，不等待 A。
本轮新增的是独立采集代码和实际执行证据，不是再次写采集计划；也不是 NOVOVM 修复。

## 交付与边界

实现见 [scripts/diagnostics/rbp-call-capture](../../../../../scripts/diagnostics/rbp-call-capture/README.md)：

- MASM 直接记录同次间接 CALL 前后 RBP/RSP、实际返回位置和目标地址，期间无调试器暂停。
- 线程预分配 192 字节记录；线程/进程创建时间、调用序号、parent、depth、入口 RSP、
  返回地址和栈边界关联调用。正常返回和 SEH 分开，异常不伪造 post-call 寄存器。
- 独立 Python 校验原始二进制记录、测试 PE 指令字节，以及跨线程/序号复用等反例。
- 目标只有新建独立进程中的测试 callee，以及真实 `ntdll!RtlReAllocateHeap` 对新建私有堆
  的操作。没有加载 NOVOVM 节点，没有原网络负载，没有读取原库/身份/失败转储。

## 实际结果

三个最终执行进程的编译、运行退出码均为 **0**，无超时。
脚本上限每个进程 60 秒，均自然结束。精确时间、PID、EXE/PDB/源码/ntdll 哈希见各执行 manifest。
公开文本仅将 CRLF 规范化为 LF；manifest/analysis 中的输入哈希仍指本机保存的原始字节。
实际编译源码副本、二进制记录、EXE/PDB 和未规范化输出保留在各 `target/c-rbp-call-capture-*`
目录，不上传可执行文件或转储。仓库源码的换行规范化不改变已编译指令。

| 检查 | 实际结果 | 限制 |
|---|---|---|
| 合法临时修改 RBP 并恢复 | 未误报 | 独立汇编 callee |
| 故意违反 RBP 保存约定 | 同次 before/after 匹配，唯一违规 | 只是采集器阳性对照 |
| 具体修改指令 | 最终测试 PE RVA `0x33ac`，字节 `48 81 f5 00 40 00 00`，`xor rbp,0x4000` | **不是 NOVOVM 故障指令** |
| 四线程与递归 | 2800 条记录校验，栈地址复用仍用不同调用序号 | 非原生产线程调度 |
| SEH | 1 次专用 marker 异常，单独 state=3，context_gap=1 | 不宣称覆盖全部 unwind/NtContinue/longjmp |
| 不完整/混合记录反例 | 改 RSP、重复序号、混线程、把展开标成正常返回均被独立解析器拒绝 | 校验器资格，非节点修复 |
| 容量满 | 拒绝执行无记录目标并计数，未覆盖记录 | 不能把它原样接入生产热路径 |
| 私有堆真实返回记录 | 单线程最后一批 4096 条，四线程最后一批 16384 条通过 | 未出现原始故障 |

同一段 `CallCapture` COFF 机器码在三个最终构建均为 112 字节、相同 SHA256；
见 [wrapper-identity.json](wrapper-identity.json)。这不表示整个 EXE 相同或与原 a254 相同。
汇编序言的 `push rbp` 与 64 字节分配有对应 unwind 信息；见 [unwind.txt](unwind.txt)。

## 实际干扰：不能签收为原故障低干扰采集

交替 AB/BA，预热、清记录和磁盘导出不在计时区间。没有每调用计时器。
以下 P50/P95/P99 是**批次平均耗时的分位数**，不是单次调用尾延迟。

| 负载 | 基线 P50 | 采集 P50 | P50 增幅 | P95 增幅 | P99 增幅 |
|---|---:|---:|---:|---:|---:|
| 单线程私有堆，每模式60批 | 42.97 ns/操作 | 57.28 ns/操作 | +33.30%（+14.31 ns） | +36.23% | +36.01% |
| 四线程共享私有堆，每模式120批 | 253.40 ns/操作 | 297.36 ns/操作 | +17.35%（+43.95 ns） | +15.19% | +26.79% |

四线程端到端吞吐从约 3.99M 降到 3.33M 操作/秒；进程 CPU 累计从 1.859375 到
2.21875 秒。单线程 CPU 计数有明显量化，不能用两边同为 0.015625 秒推导无 CPU 开销。
实际节点查询延迟、调度、长期故障概率未测，不能拿纳秒绝对开销较小来宣称不影响原时序。
公开明细：[analysis.json](analysis.json)、[single2/batches.csv](single2/batches.csv)、
[concurrent2/concurrent.csv](concurrent2/concurrent.csv)。

## 过程中发现并保留的采集器问题

首轮单线程和并发进程正常退出，但最后一轮是基线，导出时记录已清零；独立解析拒绝
将其作为完整堆调用证据。原 `run1`、`concurrent1` 输出与失败说明保留。
改为在最后一个采集批次计时结束后、下一基线清空前导出；仅重跑受影响的性能采集。

另在本工具汇编审查中，将合法 callee 的恢复值见证放到连续 `pop/ret` 尾声之前，
避免在 `pop rbp` 和 `ret` 之间插入普通指令。实际恢复仍由外层 post-call 记录证明。
这一变更做了新的 Lifecycle 定向验证；不是原节点修复。所有旧输出未覆盖。
见 [preserved-method-failures.json](preserved-method-failures.json)。

## 尚未做到的事，不能混淆

1. **原始 RBP 首次错位未定位。** 只在故意违约 callee 中证明精确指令；未把对照错位
   当作 PID34452 的 `0x2A0` 来源，也未修改 String、IndexMap、memcpy 或 AOEM。
2. 普通 before/after 只能把返回后的违规缩到一个 CALL 区间，不能自动给出内部首次写入。
3. PID34452 的堆 cookie fast-fail 可以发生在子调用返回前。外层 wrapper 的 post-call
   记录不能解决这一情况。对未知上下文恢复只有 gap 标记，不具有完整恢复历史。
4. wrapper 添加栈帧，且记录后恢复自身保存的 RBP 以保护隔离测试；禁止把这当成生产容错
   修复。RSP 或记录指针被破坏时可能无法完成采集。
5. 不用于原节点长期运行。原库、身份、233 MB 原 Full Dump 和历史失败现场未访问或改变。
   本轮没有 TTD、PageHeap、调试器附加、服务操作、原节点重启或双中继恢复。
