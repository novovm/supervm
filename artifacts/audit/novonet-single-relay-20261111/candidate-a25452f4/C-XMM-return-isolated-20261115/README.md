# 同次status返回边界采集实际结果

## 结论

一次隔离实验已经执行。未改写的a254基线四节点均按原生120秒上限退出0。
向量采集阶段约38.17秒结束，目标PID43712自行退出0xC0000005，其余三个隔离对端由控制器停止。
取得211899968字节Full Dump，SHA-256为`6752ad40c591c2a5e9fde9f8d788ae14150cf08463647173a0b14ff585495ebe`。

同一份DMP中保留1748条连续事件，6次调用走到archive初始化前，第7次调用在profile子调用内终止。
所有保留事件的XMM6/XMM7原始字节均与该副本的合法模板一致，独立核验与guard标志一致。
首次XMM错位仍未捕获，诊断副本对本次访问违规的影响仍未排除。
本轮未完成120秒干扰检查，当前方法不具备持续取证资格，入口已冻结，没有自动重试。

## 同次失败调用的最后正常边界

故障线程为15828。第7次status的入口事件序号为1507，RSP为0xf3bd3ef0e0，RBP为0xf3bd3ef160。
本次活动调用保留242条事件，最后事件为1748，对应调用RVA0x777b65返回。
该点位于signature_work发布时旧Value释放之后，XMM6/XMM7仍等于合法空表模板。

随后status执行RVA0x777bb4的调用，目标RVA0x75c4a0。
DMP中保存的父帧返回地址为0x777bb9，与该实际未返回子调用吻合。
原始有限机器码将其关联到profile快照路径。
该子调用的格式化执行链最终在String::write_str调用的两字节复制中发生访问违规。
本次尚未执行到archive_work的0x77823e/0x778245，未观察到此前36TiB分配路径。

本次动态记录覆盖signature构造及发布过程中旧Value释放返回，最后实际采样点为0x777b65。
之后原始机器码用XMM0–3搬移新值，0x777ba9完成发布，再进入profile子调用。
发布完成后的父帧向量没有独立采样，未将0x777b65表述为完整发布后的采样。
子函数内部临时使用非易失向量寄存器具有独立的保存恢复生命周期，原始异常上下文的值不能直接用于判定父调用返回违约。
本次调用未返回，因此尚不能确认它会返回异常XMM值。

## 实际异常

| 项目 | 现场 |
|---|---|
| 目标退出码 | 0xC0000005 |
| 异常线程 | 15828 |
| 故障模块 | VCRUNTIME140.dll |
| 故障RVA | 0x11268 |
| 故障指令 | movzx ecx,word ptr [rdx] |
| ExceptionInformation[0] | 0，读访问 |
| ExceptionInformation[1] | 0xffffffffffffffff |
| 原始RDX | 0x0000bc2520b34e04 |
| 本次复制长度 | 2字节 |

异常参数中的地址与指令使用的RDX分别按原始字段记录。
离线栈涉及`status → 0x75c4a0子调用 → collect/from_iter → format_inner → core::fmt::write → 数字格式化 → String::write_str → VCRUNTIME复制`。
精确原PDB缺少部分节点源码调试流，最近的profile::elapsed+0x50df符号没有被当成具体源码归属。
子调用和相关标准库原始代码覆盖区间与原a254逐字节相同，校验摘要见actual-dump-analysis-public.json。
这些代码页相同仍不足以排除父帧诊断改写造成的影响。

## 记录完整性与性能资格

Full Dump含23个线程上下文和403个Memory64范围。
同次内存事件序号1至1748连续，无环形覆盖、无关联孤儿，冻结标志为false。
另以DMP中的原始32字节逐条比较合法模板，1748条全部匹配。
6个完成调用及第7个活动调用独立关联，未拼接不同status实例。
完整活动调用的脱敏事件见active-call-events-public.jsonl，其他完成调用仅保留摘要。

采集组样本量、持续时间和负载状态与基线不齐，未据此计算合格干扰比例。
