## 原a254实际调用关系

源码固定为a25452f4c49be37cd984e650f2079642e6c273b3，文件哈希与功能位置见functional-map-public.json。

| 功能 | 实际入口和依赖 | 对照限制 |
|---|---|---|
| 周期状态查询 | 主循环定时调用network.observation与product.status | 删除报告文件路径只取消文件写入，status仍执行 |
| 状态查询时机 | last_progress_report_at初始化为已到期，退出后另有无条件status | 拉长间隔仍有启动和退出查询，不能叫status完全关闭 |
| profile::snapshot | 每次status无条件调用 | PROFILE_STAGES=0仅关闭stage计时，不取消snapshot |
| native_delivery | 环境变量开启，或probe通过原子标志显式开启 | probe存在时，环境变量0不能覆盖显式开启 |
| transport.objects | network probe启用后保留并在status中快照 | 与native_delivery需作为一个可核验的关闭组处理 |
| archive_work | status无条件构造reads_started等已有计数的JSON摘要 | 此处读取计数，未启动ArchiveRead，没有独立开关 |
| 实际归档读 | recovery路径创建ArchiveRead后增加archive_reads_started | 需与archive_work计数摘要构造区分 |
| JSON和字符串格式化 | status内部构造Value，profile逐字节格式化；之后可编码输出 | 删除输出或关闭stage计时不能取消内部格式化 |

普通nov_chainStatus也会调用完整status，当前原二进制没有“仅基础字段”的普通查询模式。
因此，用户矩阵中的A/B及完全关闭周期status的E，无法通过已查到的原a254开关按定义执行。
它们在矩阵中标为不可执行，没有制造虚假的关闭组。若以后使用不同二进制增加功能开关，应另行标明构建差异。
