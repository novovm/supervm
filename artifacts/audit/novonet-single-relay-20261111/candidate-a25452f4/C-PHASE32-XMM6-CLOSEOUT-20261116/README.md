# Phase 32：两次 XMM6 恢复故障对照收口

基于2b90ffec。本轮只比较PID13020与PID38324的重复恢复故障和保存槽生命周期。RSI/输出索引分支以2b90ffec阶段收口，降为未解释的现场差异；不再作为当前优先因果线索。

结论：两份现场的恢复指令、异常访问类型及全1报告地址一致；当前保存槽均符合原初始化常量，未观察到共同的保存槽载荷损坏。现有转储仍不能解释首次异常原因，本轮停止继续事后推断。没有生产修复，也没有新的运行或取证任务。

## 1. 恢复指令和异常记录：可比部分一致

| 项目 | PID13020 / 875 | PID38324 / a254 |
|---|---|---|
| RIP | 0x7ff77e74f59d | 0x7ff770faf36d |
| RVA | 0x65f59d | 0x84f36d |
| 函数相对偏移 | insert_full+0x31d | insert_full+0x31d |
| RIP处捕获字节 | 0f 28 75 20 | 0f 28 75 20 |
| 指令 | movaps xmm6,[rbp+0x20] | 同左 |
| ExceptionCode | 0xc0000005 | 0xc0000005 |
| ExceptionInformation[0] | 0，读 | 0，读 |
| ExceptionInformation[1] | 0xffffffffffffffff | 同左 |
| 计算出的16字节操作数起址 | 0x3d4f8ee640 | 0x3e48fee2b0 |
| 对齐/跨页 | mod16=0，不跨4KiB页 | 同左 |
| 保存槽16字节被捕获 | 是 | 是 |

复用Phase29已经完成的完整函数归一化一致性、序言/尾声及展开检查，本轮不重做该清单。这里确认的是RIP处被转储保存的机器码和两个终态；不是逐指令执行轨迹。

## 2. 栈页面状态：不能把新FullDump的证明推广给旧MiniDump

PID38324包含MemoryInfoList：保存槽位于Base=0x3e48f9c000、RegionSize=0x64000区域，State=0x1000（MEM_COMMIT）、Protect=0x4（PAGE_READWRITE）、Type=0x20000（MEM_PRIVATE）。这是转储时刻的映射；不等于故障瞬间页表/权限的完整历史。

PID13020没有MemoryInfoList、没有FullMemory标志，只有包含保存槽的栈字节。旧LLDB的r??也不是PAGE_READWRITE证据。旧现场的实际故障时页面状态未知，不能写成“两次都已证实可读写页”，也不能把缺失元数据写成页面不可读。

两者共同成立的是对齐、捕获到操作数字节、相同异常参数。两次均缺少可用于解释本次访问失败的故障时内核陷阱号/错误码、页表及前后执行历史。

## 3. 保存槽生命周期：当前值支持同种正常流程，没有历史首次破坏记录

### 上游常量至保存槽

| 项目 | PID13020 | PID38324 |
|---|---|---|
| status中XMM6常量加载 | RVA0x7725e6 | RVA0x7721e6 |
| 16字节常量RVA | 0x24f0ed0 | 0x24f5410 |
| insert_full保存XMM6 | RVA0x65f2a6 | RVA0x84f076 |
| 槽内两个qword | [0x7ff7805e0ec0,0] | [0x7ff772c55400,0] |
| 与对应原EXE常量比较 | 应用记录在案的DIR64加载重定位后相同 | 同左，并与捕获常量字节直接相同 |

常量第一个qword指向各自镜像内的静态16字节全FF块，第二个qword为0。不是把不同进程地址当同一对象；比较的是对应二进制、RVA和加载重定位后的相同结构。PID13020未捕获该常量页，因此其比较来自匹配原EXE和实际加载基址，不冒称直接读到了旧进程的常量页。

在这条活动调用链中，profile快照、collect_seq、Value::serialize及SerializeMap::serialize_value没有直接重定义XMM6；按正常ABI传递，上游初始化值应保留到insert_full入口。这里是限定代码路径下的来源关系，不是观测到每次已经返回的子调用都守约。

### 当前恢复前的暂用状态

insert_full保存XMM6后，会用它构造哈希控制字节比较掩码。PID13020的临时定义对应RVA0x65f2f1，PID38324对应0x84f0c1。捕获的XMM6分别为重复0x30、重复0x3f，均与各自捕获hash的高7位一致。它们是当前函数暂用值，不能直接当成调用者保存值。

因此两份截面均与以下流程相容：

`上游常量 → 本帧XMM6保存槽 → XMM6暂作哈希掩码 → 正常恢复指令处异常，RET未执行`。

保存/恢复使用同一当前帧区间的关系复用Phase29结论。新增的是保存槽现存载荷与上游常量的对应关系。当前没有看到保存槽被同一种坏指针或坏位型替换的证据；MOVAPS读取的载荷位型也不能独自解释该内存访问异常。

但“两个截面支持同种流程”不等于“已记录两次相同生命周期”。两份转储都没有入口保存时刻、每次嵌套调用返回、槽内中间写入及恢复前一刻的独立记录；不能判断槽是否曾被写坏后恢复、上下文是否曾转移，或故障时CPU实际访问条件是什么。本轮不再从这些缺失历史中猜测首条破坏指令。
