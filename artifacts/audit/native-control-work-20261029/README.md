## 测量结论：重复正文工作不是本轮秒级停顿的主要解释

沿既有 profile 记录编码、OutgoingMessage 摘要、拼接/解码/证据验证、正文 ID、
计费编码。计数覆盖全部调用；明细固定最多 2,048 条，记录 ≥1 ms 的片段。
网络周期为开始→开始，离开网络轮询的间隔为前次结束→本次开始；后者不是 CPU 空闲。
记录默认关闭，不参与协议或资源判断，不为计时重新编码或计算摘要。

基线 65,536 笔持续在途 CPU 诊断轮：2,038.067161 TPS，32.155957 秒，
P99 4.997556 秒；64 高度各 1,024 笔，四节点账务及冷恢复通过。

各节点并行运行，不能把四节点累计时长相加当作端到端节省。
全程最大轮询间隔约 52–58 ms，最大片段多数不与这些同步正文工作重合。
因此不能把该假设当成完整根因，也不能据此增加线程或并发。

## 最小修复与独立验证

原 AssetBody ID 计算已经编码完整 payload。现在把该次编码的准确 wire 长度
同时返回给原正文/后继持有者，计费不再编码第二次。只复用长度，不缓存授权或计算结果。
完整 wire 长度为 payload＋11 字节；正文 ID 仍哈希原域、原 payload 长度和 payload，
不把外层前缀或 wire 长度误放入 ID。旧 Body/APFL 去重与计费顺序不变。
计费依旧为两份 wire＋展开正文＋原 metadata/nonce 预算，没有减少资源计费。

新增独立 wire/transcript、恰好上限/少一字节及旧路径反例；5 项正文测试、
517 项原生回归、883 项网络默认回归和严格 Clippy 已通过。

修复版 CPU 诊断轮：2,121.808364 TPS，30.886861 秒，P99 4.631934 秒。
64 次计费长度读取每节点累计低于 0.01 ms；正文 ID 成本未被转移或隐藏。
总时间较前轮少 1.269096 秒，**不能把它全部归因于约 0.10 秒的重复编码消除**；
慢高度、到达时序和诊断负载也发生变化。关闭诊断的同字节比较另列，不以本轮证明稳定提速。
