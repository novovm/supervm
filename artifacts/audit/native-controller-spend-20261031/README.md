# 普通资产账户控制钥直接花费

开发基线 `a7759d70`，分支 `dev/mldsa65-identity-closure`。
本轮按用户最新决定取消普通账户强制 grant；性能和发布验收分别记录。

**结果：Controller 普通支付、原节点恢复及六轮65K通过；持续供给约2186–2275 TPS，
未恢复历史12K，不签性能闭环或发布完成。**

## 合同与原路径

- 复用资产账户现有 management key 作为 controller，不引入账户类型等级或另一套权限系统。
- NUAS v3 签名明确绑定 Controller / DelegatedGrant；APFL03 保留结构列和逐笔 ML-DSA-65 签名。
  原 node → exec → bindings → AOEM 统一语义不变，旧 v2 不重新解释，无降级入口。
- Controller 普通支付不读、扣减或写回 grant；仍核对当前控制钥、账户代次、active、交易
  有效期、nonce、余额及费用。受限委托仍严格消费原有限额；恢复钥不能直接扣款。
- 原初始化和运行中开户可使用空 grants，账户 nonce 独立初始化。资金来自原转账，不增发。
- 账户地址/状态键/nonce 域不变。程序、效果与回执合同承诺同步更新；不迁移旧数据库，
  不改 main、不替换正式随包 AOEM、不部署、不清理现有数据。
- 查询 NVQUERY6 明确 authority，grant 字段只描述实际委托记录；Controller 的零预算不是
  “无限授权”。查询权限状态按报告高度与所提交 intent 的交易窗口解释，不是到账凭证。

减少的工作：普通交易每个独立 grant 的3个声明键及其读取/解码，完整效果计划中的
grant presence/额度判断、预算扣减和状态回写；仍复用原批捕获、签名事实、后继执行和 journal。
实际收益需由下方固定制品与真实四节点测试证明，不能将键数减少直接换算 TPS。

## 验证记录

以下结果绑定本轮 V3 制品和新签名语料；
与旧 grant-only 合同只能比较业务条件，不能宣称跨合同同字节。

### 测试边界与已发现的夹具问题

- 最终协议70、权限策略22、执行层83项默认测试通过（执行层29项显式忽略）；
  原生流水线562项通过、144项显式忽略。均以单测试线程执行，不替默认并发/WSS验收。
- 原生真实签名首轮10项中9项通过，1项在执行前拒绝候选库：
  `actual_mldsa_signature_and_same_parent_preflight_reject_stale_authority`
  硬编码随包路径，不接受现有 `NOVOVM_AOEM_TEST_LIBRARY` 显式候选选择。
  旧冻结v8在相同环境复现同一拒绝；本轮只沿其他签名夹具已有方式适配，仍检查
  密钥生成与验签使用同一库，保留manifest/capability检查。不替换正式随包库。
- Controller专项除检查不读取grant外，还以同一控制钥的原grant键独立读树，确认没有
  合成grant；已有受限委托仍逐项核对不被Controller扣款改变。完整负载结束后的
  四库审计同样显式读取该grant位置，额外读取在TPS计时外，不污染生产热路径。
- 早期未筛选的node整包测试触发旧Host即时执行拒绝，已停止该轮，日志保留。
  `mainline_query_cut_c_standard_ed25519_allows_execution` 在旧冻结v8与新候选中
  都被相同默认禁用规则拒绝；没有打开 `NOVOVM_ALLOW_LEGACY_HOST_EXECUTION`。
  只复现了这一具体对应项，不把其余未逐项复现失败统称已结案，也不声称整包通过。

## 65,536笔真实主链结果

共同条件：4个原节点进程/独立库，1024付款账户各64笔、1个独立共享收款方，
原8192持续在途、1024行/8 MiB展开预算，ML-DSA-65，业务执行均CPU callbacks。
实际六轮均64高度、每高度1024行；首发尝试至四节点全部最终回执查询可见为计时终点。
保持原共识、费用、nonce、交易有效期与生产超时；测试总期限显式600秒，不是提速因素。
CPU→GPU→CPU指三次独立实验的顺序，不是验签内核在CPU/GPU之间来回执行。
实际选择以每轮顶层 `signature_backend` 为准，继承环境不覆盖显式CPU/GPU参数。

## 与旧合同比较和剩余阻断

- 旧v8同字节样本为1946.99/1885.82 TPS，新样本2304.19/2298.88；但NUAS合同、
  初始权限树、密钥和签名语料不同，不能把差额当成单因素同字节收益。
  新CPU首轮P99 5.340495秒也比旧v8 CPU 5.162208秒更差。
- 普通支付实际消除了grant声明/解码/预算判断/扣减/回写；没有减少公钥或签名内容。
  每1024行APFL仍为5,453,061字节（旧5,453,052），展开5,579,776字节。
  65K APFL逻辑正文348,995,904字节，不是物理网络总流量。新增权限模式在结构列中
  每帧仅多9字节；独立公钥负载的压缩率不能套用16个重复公钥的约38%成绩。
- 本轮没有测物理网络字节、重传、峰值内存或重新拆分网络函数耗时。不能用旧网络
  诊断直接宣布已经解释新轮次的全部等待，更不能把去掉grant当成解决了网络负担。
- 1024账户持续吞吐仍约2.2K，12K性能目标未完成；GPU未证明稳定整链优势。
  65536个独立付款账户扩展场景、默认并发/WSS历史间歇问题、Linux、多机、完整候选CI
  与正式随包AOEM资格仍单列，均不因这次本地通过而关闭。
- main、正式随包库、A-D服务和既有数据未修改。本检查点是同一开发分支的账户策略
  纠正及完整本地验收，不是主网上线、完整身份迁移或性能恢复签收。
