## 一次业务联调的执行顺序

各机先把候选和实际状态交给 A 汇总。A/B/D 准备就绪且共同创世、身份、协议与可达性一致后，再启动 C；保持原四验证者、三票门槛及现有网络所有者，不为了联调另造网络或更换身份。

先用原生客户端提交**一个已授权的真实业务对象**，记录请求摘要/交易哈希、发送与接收两端逐对象记录；然后核对四机同一已发布高度、head/状态根、至少三票的有效最终性证明，以及对应的业务回执和冷恢复。若当前系统尚无可提交的授权对象或不能形成收据，就明确停在相应边界，不能以传输计数补作结果。资产转移、收费、ASAS 授权等各自按现有权限和业务契约单独验收，不在此交接中默认启用。
