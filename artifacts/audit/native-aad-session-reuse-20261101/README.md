基线 `8c778ab9`，继续 `dev/mldsa65-identity-closure`。
**实现与正确性通过；局部调用确实减少工作，整链稳定性能门禁未通过。**
本轮只改原 `product_overlay::E2eSecureChannelV1` 的逐报AAD准备，
不改账户、签名、共识、补片、候选、配额、超时、GPU或AOEM接口。
main、正式随包库和部署保持不动。

后续[原UDP最终wire缓冲复用](../native-send-buffer-20261101/README.md)以本轮
`16cb4cec`冻结制品为基线，消除UDP封装中的独立密文及身份克隆，保留通用envelope API。
该轮局部减少工作、16轮65K及恢复通过，但持续性能仍有负向；不改写本页AAD历史成绩。

## 改掉的工作

原来每次seal/open均调用 `secure_frame_aad_v1`，从空Vec重复拼接域、版本、
会话及双方身份，再写序号和nonce。现在：

- 原握手完成构造channel时，两方向各建立一份精确容量AAD缓冲。
- 原seal/open每包只覆盖20字节sequence/nonce尾部；不分配或增长AAD缓冲。
- Open仍先检查版本、会话、身份、nonce和重放，再使用该方向模板。
- 原独立nonce/tag、失败不更新重放、序号耗尽、帧编码与完整性验证不变。
- 无新队列、线程、凑批等待或跨会话缓存；两份缓冲由原channel拥有并随其zeroize/drop。

输出envelope仍需原有字符串/密文所有权；不是把所有逐包分配都消掉。
原地加密及owned接收复用密文缓冲本来已存在，本轮没有把它们算成新成果。
ChaCha20Poly1305::new在当前依赖中只复制32字节密钥，不持有扩展运算上下文；
本轮未为它再存一份会话cipher或改变一次性Poly1305材料。

## 局部Seal/Open对照

[原始日志](isolated-benchmark.log)为65536次完整seal或owned-open，包含帧处理、
密码运算和输出分配；同一组会话/密钥/序号/正文进行旧参考→当前原方法→旧参考，
三次重复，组批1/8/16/32，不增加等待。Open输入副本在两组计时前准备。
旧参考保留原未缓存AAD算法，不等于完整旧节点；其不含生产诊断span包装，关闭诊断
仍可能略偏向参考。正式节点旧/新对照另列，不从本表推算TPS。

这验证已有开户路径，没有将它冒称本轮新增功能；其他产品门禁另列。

首次启动失败是**本轮打包遗漏**：候选目录缺少native-client，测试器在启动前退出101。
已补构建并复制匹配客户端，完整复跑通过，不将它写成历史节点缺陷。
失败保留于 `target/native-aad-session-reuse-20261101/20261101-112718-35652-recovery-candidate-unobserved/`。
成功恢复之后，外层错误使用LASTEXITCODE检查PowerShell脚本返回值，误报停止后续微测；
真实harness/run.json为退出0、completed=true。随后已独立完成局部复测及
[19项最终定向测试](aad-targeted-final.log)，不把包装器错误算成节点故障。

## 本轮结论

保留原会话内的简单AAD复用候选：每包不再分配/拼接静态AAD，线格式与安全语义保持。
**不能登记为整链稳定提速：局部收益兑现，但入口CPU成本、静态GPU吞吐及持续CPU
仍有反向样本。4K未达到，12K未恢复。** 不推进main、正式库或部署，不改Auto。
下一性能工作应对剩余真实逐包运算/发送工作量单独验收，不能用AAD收益承诺恢复目标。

[run.ps1](run.ps1)只调用原冻结测试器及原进程观察脚本；不创造新交易入口或运行时。
所有原数据库、journal和观测证据保留。中间不触发完整云端CI。
